# คู่มือติดตั้งและอัปเดต BPP-VMS หลายสถานที่

## สิ่งที่อยู่ในชุดนี้

- `BPP-VMS-FullBackup.tar` เป็นชุดติดตั้ง v1.0.0 แบบไม่เข้ารหัส
- `.sha256` ใช้ตรวจว่าไฟล์ดาวน์โหลดครบ แต่ไม่ใช่ลายเซ็นดิจิทัล
- BAT สำหรับตรวจสอบ ติดตั้ง และอัปเดตแบบกดครั้งเดียว
- โฟลเดอร์ `tools` เป็นเครื่องมือที่ BAT เรียกใช้ ห้ามแยกออกจากกัน

TAR ไม่มีภาพ/วิดีโอที่กล้องหรือ LPR บันทึกไว้ และไม่มี Frigate event DB, Git,
cache, JWT/TLS/DuckDNS/bot secret เดิม แต่มีผู้ใช้และ password hash, สิทธิ์,
auth audit, Watchlist/ประวัติ LPR แบบข้อความ, NAS state/config, โมเดล และ Docker images
ครบตาม manifest เนื่องจาก TAR ไม่เข้ารหัส ผู้ที่ได้ไฟล์อาจเข้าถึงข้อมูลภายในที่เก็บไว้ได้
จึงต้องจำกัดสิทธิ์ Google Drive และเครื่องที่ดาวน์โหลด

## เตรียมเครื่อง Windows 10/11

1. ติดตั้ง Docker Desktop รุ่นที่รองรับ WSL2 และตั้งให้เริ่มเมื่อผู้ใช้ล็อกอิน
2. ติดตั้ง NVIDIA driver ที่ทำให้ `nvidia-smi` เห็น GPU (รองรับตั้งแต่ RTX 3060 6GB ถึง RTX 5060 Ti 16GB ตามชุดนี้)
3. ไดรฟ์ D: ต้องมีพื้นที่พอ และ `D:\BPP-VMS` ต้องยังไม่มีไฟล์อื่น
4. ดาวน์โหลดไฟล์ทั้งโฟลเดอร์จาก Google Drive แล้วล็อกอิน Windows ด้วยบัญชีที่จะใช้รันระบบ

## ติดตั้ง

1. กด `Verify_BPP-VMS.bat` ก่อน ถ้าไม่ผ่านห้ามติดตั้ง
2. กด `Install_BPP-VMS.bat` และตอบ UAC
3. เลือก `Clone` เมื่อต้องการเก็บรายการ/credential กล้องเดิม (กล้องทุกตัว, detect และ record ยังปิดอยู่)
4. เลือก `NewSite` เมื่อเป็นไซต์ใหม่ที่ต้องไม่มีข้อมูลกล้องต้นทาง
5. ใส่ชื่อไซต์และ IPv4 ของเครื่องใหม่ ตัวอย่าง `192.168.1.50`
6. รอจนขึ้นคำว่า “สำเร็จ” เท่านั้น แล้วเปิด `https://<IP-เครื่องใหม่>`

ใบรับรองเริ่มต้นเป็น self-signed ที่มี IP ของเครื่องใน SAN เบราว์เซอร์จึงอาจเตือนครั้งแรก
ระบบสร้าง node ID, Compose project, JWT key, TLS key และ shared secrets ใหม่ทุกเครื่อง
Telegram/Discord/Federation/DuckDNS/ACME ยังว่างและปิดไว้ ส่วน NAS config ถูกโคลนไว้ให้ตรวจ

หลังติดตั้ง Scheduled Task จะทำงานเมื่อบัญชีนี้ล็อกอิน รอ Docker Desktop พร้อม แล้วจึงเปิด
Compose และตรวจ health/config โดยไม่เปิด profile `public-edge` การเริ่มก่อนล็อกอินไม่ได้รับรองในโหมด WSL2 นี้

## อัปเดตจาก Google Drive

1. ดาวน์โหลดโฟลเดอร์ update รุ่นใหม่ที่มี TAR, SHA-256, BAT และ `tools`
2. เก็บ Update TAR เพียงหนึ่งไฟล์ในโฟลเดอร์ แล้วกด `Verify_BPP-VMS.bat`
3. กด `Update_BPP-VMS.bat` ระบบจะหยุด service, snapshot รุ่นเดิม, โหลด images ใหม่ และตรวจ health
4. ถ้าผ่าน จะเก็บ rollback ล่าสุด 3 รุ่น ถ้าไม่ผ่านจะคืน application/metadata รุ่นเดิมและเปิดรุ่นเดิมกลับ

อัปเดต production รับเฉพาะเวอร์ชันที่เพิ่มขึ้นและแพ็กจาก clean `main` ส่วนไฟล์ `-dev.*`
ถูกปฏิเสธตามปกติ ค่าไซต์ `.env`, กล้อง, TLS, Watchlist, NAS, storage และ LPR media ไม่ถูกแทนที่

## DuckDNS/ACME และการซิงก์ในอนาคต

ความสามารถ `public-edge` ถูกเก็บไว้แต่ไม่ทำงาน ต้องกำหนด subdomain/token และเปิด profile
โดยตั้งใจก่อนจึงจะใช้ DuckDNS/ACME ได้ Federation shared secret และการซิงก์ข้ามไซต์ยังว่างไว้
สำหรับ NAS กลางในอนาคตควรปรับ path/สิทธิ์ต่อไซต์และทดสอบทีละเครื่องก่อนเปิดซิงก์จริง

## เมื่อพบความล้มเหลว

- การสร้างแพ็กต้นทางล้มเหลว: ต้นทางต้องคงหยุดไว้จนตรวจ TAR ผ่าน แล้วค่อยเริ่ม service เดิม
- การติดตั้งล้มเหลว: ระบบยังปิดและไม่มี autostart ให้แก้สาเหตุแล้วกดติดตั้งซ้ำ
- การอัปเดตล้มเหลว: ตรวจข้อความว่า rollback ผ่านและรุ่นเดิม active หาก rollback ไม่ผ่านให้คงเครื่องปิดและซ่อมก่อน
- ห้ามลบ `.bpp-release`, `.bpp-rollback` หรือ Docker volumes ด้วยตนเองระหว่างติดตั้ง/อัปเดต

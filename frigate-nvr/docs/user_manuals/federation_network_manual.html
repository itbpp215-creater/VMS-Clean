คู่มือการตั้งค่าเครือข่ายข้ามหน่วยงาน (Federation)

เลือกรูปแบบเครือข่ายของหน่วยงานปลายทาง

คลิกเลือกสถานการณ์ของหน่วยงานที่คุณต้องการดึงภาพกล้องมาแสดงผล

🟢 กรณีที่ 1: มี Public IP

หน่วยงานปลายทางใช้อินเทอร์เน็ตองค์กร/บ้าน สามารถขอทำ Forward Port ที่เร้าเตอร์หลักได้

🟠 กรณีที่ 2: ไม่มี Public IP (ติด NAT)

ใช้อินเทอร์เน็ตซิม (4G/5G) หรือเน็ตองค์กรที่ถูกบล็อกพอร์ต ไม่สามารถทะลวงจากภายนอกเข้าหาเครื่อง NVR ได้

🔴 กรณีที่ 3: ไม่มี Internet เลย

เป็นเครือข่ายปิด (Air-gapped) ของตำรวจ/ทหาร หรืออยู่กลางป่าที่ไม่มีสัญญาณใดๆ

🟣 กรณีพิเศษ: กล้องใส่ซิม (4G/LTE Camera)

กล้องวงจรปิดแบบใส่ซิมในตัว (Hikvision, Dahua, TP-Link, Reolink ฯลฯ) ที่ไม่มี NVR คั่นกลาง

🔍 วิธีหาลิงก์ RTSP ของ NVR

สูตร URL ดึงภาพของ Hikvision, Dahua, Uniview, XMeye และวิธีค้นหาสำหรับยี่ห้ออื่นๆ

🤝 วิธีการซิงค์กล้องข้ามกองร้อย (Software)

คู่มือการตั้งค่าหน้าต่าง Dashboard เพื่อดึงภาพจากกองร้อยต่างๆ เข้าสู่จอส่วนกลาง

กรณีที่ 1: มี Public IP (ขั้นตอน 1/3)

ตรวจสอบ Public IP ฝั่งปลายทาง

1. เปิดเบราว์เซอร์ที่เครื่อง NVR ของหน่วยงานปลายทาง แล้วเข้าเว็บ whatismyip.com

2. ตรวจสอบเลข IP ที่ปรากฏบนเว็บ นำไปเทียบกับ WAN IP ภายในเร้าเตอร์ หากเลขตรงกันแปลว่าคุณได้ Public IP แท้

💡 ข้อแนะนำ

หาก IP ของคุณเป็นแบบไดนามิก (เปลี่ยนใหม่ทุกครั้งที่เร้าเตอร์ดับ) แนะนำให้สมัครและตั้งค่า DDNS (เช่น No-IP, DynDNS) ไว้ในเร้าเตอร์ เพื่อให้เรียกผ่านชื่อโดเมนแทนตัวเลข IP

กรณีที่ 1: มี Public IP (ขั้นตอน 2/3)

ทำ Port Forwarding ที่ Router ปลายทาง

เข้าไปตั้งค่าใน Router ของหน่วยงานปลายทาง (เมนู NAT หรือ Port Forwarding) ให้ส่งต่อพอร์ตเข้ามาหา IP ภายในของเครื่อง BPP-VMS (เช่น 192.168.1.100)

  • พอร์ตที่ต้อง Forward: 80 และ 443 (โปรโตคอล TCP สำหรับให้ส่วนกลางยิง API เข้ามาได้)
  • พอร์ตที่ต้อง Forward: 8555 (โปรโตคอล TCP และ UDP สำหรับให้ส่วนกลางดึงภาพสดแบบ WebRTC)
กรณีที่ 1: มี Public IP (ขั้นตอน 3/3)

ทดสอบการเชื่อมต่อ

ที่เครื่องส่วนกลาง (หรือมือถือของคุณ) ให้ลองเปิดเบราว์เซอร์แล้วพิมพ์ https://<Public-IP-ของปลายทาง> หรือ https://<ชื่อ-DDNS>

หากขึ้นหน้า Login ของระบบ BPP-VMS แสดงว่า Forward Port สำเร็จแล้ว!

🛠️ แก้ปัญหา (Troubleshooting)

- เข้าหน้าเว็บไม่ได้เลย: ผู้ให้บริการเน็ต (ISP) อาจบล็อกพอร์ตไว้ (แจก Private IP เริ่มด้วย 100.x) ให้โทรแจ้ง ISP ว่าขอปลด NAT สำหรับดูกล้องวงจรปิด
- เข้าเว็บได้ แต่ดึงภาพไม่ได้: อาจลืม Forward พอร์ต 8555 แบบ UDP

กรณีที่ 2: ไม่มี Public IP (ขั้นตอน 1/3)

ใช้ MikroTik สร้าง VPN Tunnel (SD-WAN)

เนื่องจากอินเทอร์เน็ตซิม (4G/5G) หรือเน็ตองค์กร/หอพักมักจะติด NAT ทำให้เรา "Forward Port เข้ามาตรงๆ ไม่ได้" เราจึงต้องให้ฝั่งปลายทาง "มุด" (Dial-out) ออกมาหาส่วนกลางแทน

ทำไมถึงแนะนำ MikroTik?
MikroTik เป็นฮาร์ดแวร์เร้าเตอร์ที่ราคาประหยัด เสถียร และรองรับการทำ VPN หลายรูปแบบ (เช่น WireGuard, L2TP/IPsec, SSTP, OVPN, ZeroTier) เมื่อตั้งค่าให้ MikroTik ปลายทางเชื่อมต่อ VPN มายังส่วนกลางสำเร็จ มันจะสร้าง "ท่อจำลอง" (Tunnel) ที่ทำให้ส่วนกลางสามารถวิ่งทะลุกลับเข้าไปหากล้อง/NVR ที่เสียบสาย LAN อยู่หลัง MikroTik ได้ทันที

กรณีที่ 2: ไม่มี Public IP (ขั้นตอน 2/3)

กฎเหล็ก: "ห้ามตั้ง IP LAN ซ้ำกันเด็ดขาด"

ในการทำ VPN แบบ Site-to-Site วง LAN ภายในของแต่ละกองร้อย จะต้องเป็นคนละวงกัน (Non-overlapping Subnet) เสมอ

🚨 ทำไมถึงห้ามตั้ง IP ซ้ำกัน?

สมมติว่า กองร้อย A ใช้วง 192.168.1.x และ กองร้อย B ก็ใช้ 192.168.1.x
เมื่อเซิร์ฟเวอร์ส่วนกลางต้องการดึงภาพจาก NVR ที่ IP 192.168.1.100 เร้าเตอร์ส่วนกลางจะไม่รู้เลยว่าจะต้องส่งข้อมูลลงไปที่ท่อ VPN ของกองร้อย A หรือ กองร้อย B เพราะเลขมันซ้ำกัน ทำให้ระบบ Routing รวนและดึงภาพไม่ได้เลย

วิธีแก้: แอดมินต้องแบ่งวง IP ให้ชัดเจนตั้งแต่ตอนออกแบบระบบ เช่น:

  • ส่วนกลาง: ใช้ IP วง 10.0.0.x
  • กองร้อยที่ 1: ใช้ IP วง 192.168.11.x
  • กองร้อยที่ 2: ใช้ IP วง 192.168.12.x
กรณีที่ 2: ไม่มี Public IP (ขั้นตอน 3/3)

การตั้งค่า Route ข้าม Network

เมื่อเชื่อมต่อ VPN สำเร็จ และวง LAN ไม่ซ้ำกันแล้ว ขั้นตอนสุดท้ายคือการชี้เป้าหมาย (Routing):

  1. ที่ MikroTik ส่วนกลาง: ให้เพิ่ม Static Route เพื่อบอกว่า "ถ้าเซิร์ฟเวอร์ VMS จะเรียกหา 192.168.11.x ให้วิ่งผ่านท่อ VPN (Interface) ของกองร้อย 1"
  2. ที่ MikroTik กองร้อย 1: เอาสาย LAN จากเครื่อง NVR มาเสียบเข้าที่พอร์ต LAN ของ MikroTik (NVR จะได้ IP เช่น 192.168.11.100)

จากนั้นที่เครื่อง VMS ส่วนกลาง คุณก็สามารถไปที่หน้า "เพิ่มกล้อง" แล้วกรอก IP 192.168.11.100 ได้โดยตรงเลย!

🛠️ แก้ปัญหา (Troubleshooting)

- Ping VPN เจอ แต่ Ping ทะลุไปหา NVR ไม่เจอ: ฝั่ง MikroTik กองร้อย 1 อาจยังไม่ได้ตั้ง Default Gateway ของ NVR ให้ชี้กลับมาที่ MikroTik หรือส่วนกลางอาจจะลืมทำ Route กลับ

กรณีที่ 3: ไม่มี Internet เลย (ขั้นตอน 1/2)

เชื่อมต่อระดับฮาร์ดแวร์ (Physical Link)

เมื่อไม่มีอินเทอร์เน็ตสาธารณะ คุณต้องนำเครือข่ายของทั้งสองฝ่ายมาชนกันโดยตรงผ่านระบบปิด เลือกวิธีใดวิธีหนึ่งต่อไปนี้:

  • 1. ใช้ Hardware VPN Router (แนะนำ): ใช้อุปกรณ์ระดับองค์กร (เช่น Mikrotik, Peplink, Cisco, Teltonika) ที่รองรับ SD-WAN หรือเสียบซิม Private APN ของหน่วยงานรัฐ แล้วลากสาย LAN จาก Router ตัวนี้ไปเสียบเข้าที่หลังเครื่อง NVR โดยตรง
  • 2. ยิงสัญญาณวิทยุ (Wireless P2P): ใช้จานยิงสัญญาณ (เช่น Ubiquiti airMAX) ยิงข้ามเขาหรือระยะไกล 5-20 กิโลเมตร ทำหน้าที่เหมือนลากสาย LAN กลางอากาศ
  • 3. ลากสาย Fiber Optic: ลากสายส่วนตัว หากระยะทางไม่ไกลและสามารถเดินสายได้
  • 4. ใช้ Intranet ของหน่วยงานรัฐ: ติดต่อศูนย์สารสนเทศเพื่อขอใช้ช่องสัญญาณ MPLS ที่มีอยู่แล้ว ร้องขอให้เขาสร้าง VLAN โยง IP ของทั้งสองฝั่งเข้าหากัน
กรณีที่ 3: ไม่มี Internet เลย (ขั้นตอน 2/2)

ตั้งค่า Static Route ที่เราเตอร์

หากใช้เครือข่าย MPLS (วิธีที่ 3) หรือเราเตอร์แยก แอดมินเครือข่ายต้องทำ Static Route บนตัวอุปกรณ์ เพื่อให้ระบบ LAN ฝั่งส่วนกลาง รู้จักวิธีวิ่งผ่านเกตเวย์ไปหา วง LAN ของจุดตรวจ

🛠️ แก้ปัญหา (Troubleshooting)

- Ping หากันไม่เจอ: มักเกิดจากการติด Firewall บน Core Switch ขององค์กร ต้องประสานงานฝ่าย IT ให้เปิดอนุญาตพอร์ต TCP 443 และ UDP 8555 วิ่งข้าม VLAN
- ฝนตกแล้วภาพขาดหาย (สำหรับเสา Wireless): ต้นไม้หรือสภาพอากาศอาจบังระยะยิงคลื่น (Line of Sight) ต้องตั้งเสาให้พ้นสิ่งกีดขวาง

กรณีพิเศษ: กล้องใส่ซิม (ขั้นตอน 1/2)

เลือกวิธีการดึงภาพจากกล้อง 4G

กล้องวงจรปิดใส่ซิมทุกยี่ห้อ (เช่น Hikvision, Dahua, Uniview, TP-Link VIGI, Milesight, Reolink, Vstarcam) มักจะเจอปัญหา "ติด NAT ของค่ายมือถือ" ทำให้ไม่สามารถเรียกดูภาพตรงๆ ผ่าน Public IP ได้ คุณต้องแก้ปัญหาด้วย 3 วิธีนี้:

  • วิธีที่ 1 (ดีที่สุดสำหรับ VMS): ใช้ซิม Private APN
    ติดต่อค่ายมือถือ (เช่น AIS, TRUE) เพื่อขอจดทะเบียนซิมแบบ Private APN สำหรับองค์กร กล้องจะได้ IP ภายในวงแลนใหญ่ (เช่น 10.x.x.x) ซึ่งเซิร์ฟเวอร์ส่วนกลางสามารถ Ping หากล้องและดึงภาพได้ทันที
  • วิธีที่ 2: ใช้ Router 4G VPN แทนซิมในกล้อง
    หากกล้องมีช่องเสียบสาย LAN ให้ถอดซิมออกจากกล้อง แล้วไปใส่ใน Router 4G ระดับองค์กรแทน จากนั้นติดตั้ง Tailscale / ZeroTier ลงบน Router ตัวนั้น แล้วลากสาย LAN เข้ากล้อง (ทำเหมือน "กรณีที่ 2")
  • วิธีที่ 3: ใช้ Server ดึงภาพผ่าน P2P (ยาก)
    แบรนด์ระดับ Pro (เช่น Hikvision ผ่าน ISUP/EHome, Dahua ผ่าน Auto-Register) สามารถตั้งให้กล้อง "ยิง" ภาพเข้ามาหาเซิร์ฟเวอร์ส่วนกลางเองได้ แต่ต้องมีซอฟต์แวร์ของยี่ห้อนั้นๆ มารับภาพแล้วแปลงเป็น RTSP อีกทอดหนึ่ง
กรณีพิเศษ: กล้องใส่ซิม (ขั้นตอน 2/2)

การตั้งค่าดึงภาพเข้าระบบ (RTSP)

เมื่อคุณใช้วิธี ซิม Private APN (วิธีที่ 1) หรือ Router 4G VPN (วิธีที่ 2) จนสามารถเรียก IP ของกล้องได้แล้ว ให้ทำตามนี้:

ไปที่เมนู "กล้องในระบบ (NVR)" > "เพิ่มกล้องใหม่" จากนั้นกรอกลิงก์ RTSP URL ตามยี่ห้อกล้องของคุณ:

Hikvision: rtsp://admin:รหัสผ่าน@<IP-กล้อง>:554/Streaming/Channels/101
Dahua: rtsp://admin:รหัสผ่าน@<IP-กล้อง>:554/cam/realmonitor?channel=1&subtype=0
TP-Link VIGI: rtsp://admin:รหัสผ่าน@<IP-กล้อง>:554/stream1
Uniview (UNV): rtsp://admin:รหัสผ่าน@<IP-กล้อง>:554/unicast/c1/s0/live
Reolink: rtsp://admin:รหัสผ่าน@<IP-กล้อง>:554/h264Preview_01_main
Milesight: rtsp://admin:รหัสผ่าน@<IP-กล้อง>:554/main

⚠️ คำเตือนเรื่องกล้องตามบ้าน (Home Use)

กล้องแบรนด์เล็กหรือรุ่นสำหรับใช้ตามบ้าน (เช่น Vstarcam, Watashi รุ่นเล็กสุด, Xiaomi, Tapo) มักจะถูกล็อกระบบปิด และ ไม่รองรับมาตรฐาน RTSP/ONVIF ทำให้ไม่สามารถเชื่อมต่อเข้ากับระบบ VMS กลางแบบนี้ได้ทุกกรณีครับ แนะนำให้ใช้แบรนด์ระดับ Professional ขึ้นไปครับ

คู่มือเสริม: สำหรับ Admin

วิธีหาลิงก์ RTSP ของเครื่องบันทึก (NVR)

NVR แต่ละยี่ห้อจะมีรูปแบบการดึงภาพผ่าน RTSP ที่ต่างกันออกไป โดยปกติคุณสามารถ เปลี่ยนเลขแชนเนล (กล้องตัวที่ 1, 2, 3...) เพื่อดึงภาพกล้องแต่ละตัวออกมาได้ นี่คือรูปแบบมาตรฐานของยี่ห้อยอดฮิต:

Hikvision / HiLook / OEM (รุ่นพี่):
rtsp://admin:รหัสผ่าน@<IP-NVR>:554/Streaming/Channels/101 (กล้องตัวที่ 1)
rtsp://admin:รหัสผ่าน@<IP-NVR>:554/Streaming/Channels/201 (กล้องตัวที่ 2)

Dahua / Watashi (รุ่นส่วนใหญ่):
rtsp://admin:รหัสผ่าน@<IP-NVR>:554/cam/realmonitor?channel=1&subtype=0
rtsp://admin:รหัสผ่าน@<IP-NVR>:554/cam/realmonitor?channel=2&subtype=0

Uniview (UNV):
rtsp://admin:รหัสผ่าน@<IP-NVR>:554/unicast/c1/s0/live (กล้อง 1)

XMeye / ICSee / ยี่ห้อจีนทั่วไป (Port อาจเป็น 554 หรือ 34567):
rtsp://admin:รหัสผ่าน@<IP-NVR>:554/user=admin&password=รหัสผ่าน&channel=1&stream=0.sdp

🔍 ทำอย่างไรถ้ายี่ห้อไม่ตรง หรือลองแล้วภาพไม่มา?

วิธีที่ 1: ใช้โปรแกรม ONVIF Device Manager (ODM) (แนะนำ)
ดาวน์โหลดโปรแกรมลงในคอมพิวเตอร์ที่ต่อกับวงแลนเดียวกับ NVR โปรแกรมจะสแกนหาเครื่อง NVR อัตโนมัติ เมื่อคลิกเข้าไปที่ Live Video ด้านล่างของโปรแกรมจะ บอกลิงก์ RTSP ที่ถูกต้องแป๊ะๆ ให้คุณก๊อปปี้ไปใช้ได้เลย

วิธีที่ 2: ค้นหาจากคลังข้อมูลโลก iSpy
เข้าไปที่เว็บไซต์ ispyconnect.com/cameras แล้วพิมพ์ยี่ห้อ NVR ของคุณ เว็บจะแสดงรูปแบบ RTSP URL ที่เป็นไปได้ทั้งหมดของยี่ห้อนั้นให้คุณก๊อปไปเปลี่ยน IP และรหัสผ่านทดสอบดูด้วยโปรแกรม VLC Media Player ครับ

วิธีที่ 3: เช็คจากโปรแกรม VLC
เมื่อได้ลิงก์ RTSP มาแล้ว แนะนำให้เอาไปเปิดทดสอบในโปรแกรม VLC Media Player บนคอมพิวเตอร์ก่อนนำไปใส่ใน VMS ถ้ารูปขึ้นใน VLC ก็แปลว่าลิงก์ใช้งานได้ 100% ครับ

การซิงค์ข้อมูลกองร้อย (ขั้นตอน 1/3)

ตั้งค่ารหัสลับ (Shared Secret)

ก่อนที่เซิร์ฟเวอร์ส่วนกลางจะดึงข้อมูลกล้องจากเซิร์ฟเวอร์กองร้อยได้ ทั้งสองฝั่งจะต้องมีรหัสผ่านยืนยันตัวตนที่ตรงกันเป๊ะ เพื่อป้องกันไม่ให้คนนอกแอบมาดึงภาพของเราไปดู

  1. เข้าไปที่เครื่องเซิร์ฟเวอร์ของทั้งส่วนกลางและกองร้อย เปิดไฟล์ .env ขึ้นมา
  2. มองหาตัวแปรที่ชื่อว่า WATCHLIST_FEDERATION_SHARED_SECRET
  3. ตั้งค่ารหัสผ่านให้ตรงกัน เช่น:
    WATCHLIST_FEDERATION_SHARED_SECRET=MySuperSecretKeyBPP123!
  4. รีสตาร์ทระบบ VMS ทั้งสองฝั่งเพื่อให้รหัสผ่านใหม่มีผล
การซิงค์ข้อมูลกองร้อย (ขั้นตอน 2/3)

ลงทะเบียนรายชื่อกองร้อย (Add Node)

ที่หน้าจอ VMS ของ "เซิร์ฟเวอร์ส่วนกลาง" คุณจะต้องเพิ่มรายชื่อกองร้อยทั้งหมดลงในสมุดโทรศัพท์ (Nodes) ของระบบเสียก่อน

  1. คลิกที่ไอคอน การตั้งค่าระบบ (รูปฟันเฟือง ⚙️) ที่มุมขวาบนของหน้า Dashboard
  2. เลื่อนหาหัวข้อ "รายชื่อหน่วยงานในเครือข่าย (Federation Nodes)"
  3. กดปุ่มเพิ่มหน่วยงาน และกรอกข้อมูลดังนี้:
    • ชื่อหน่วยงาน: ตั้งให้จำง่าย เช่น กองร้อย 324, จุดตรวจ A
    • URL / IP Address: กรอกเลข IP หรือชื่อโดเมนของเครื่อง NVR ปลายทาง (ที่ทำเครือข่ายทะลุถึงกันแล้วจากคู่มือเน็ตเวิร์ก) เช่น https://192.168.11.100
  4. กดปุ่มบันทึก
การซิงค์ข้อมูลกองร้อย (ขั้นตอน 3/3)

ดึงกล้องข้ามเครือข่ายเข้าส่วนกลาง

เมื่อลงทะเบียนรายชื่อกองร้อยเสร็จแล้ว การดึงกล้องมาดูจะกลายเป็นเรื่องง่ายมาก เพราะระบบจะวิ่งไปโหลดรายชื่อกล้องจากกองร้อยนั้นมาให้เลือกคลิกเลย

  1. ไปที่แท็บ "กล้องในระบบ (NVR)" บนหน้าต่างตั้งค่า
  2. คลิกปุ่ม "เพิ่มกล้องใหม่" ที่มุมขวาบน
  3. ที่กล่อง Dropdown [- หน่วยงานอื่น -] ให้คลิกเลือกชื่อกองร้อยที่คุณเพิ่งเพิ่มเข้าไป
  4. รอระบบโหลดสักครู่ (ระบบกำลังเอา Shared Secret ไปคุยกับปลายทาง) จากนั้นจะมีกล่อง Dropdown ที่สองโผล่ขึ้นมา ให้เลือก กล้องที่คุณต้องการดึงภาพ แล้วกดปุ่ม "ดึงข้อมูล"
  5. ระบบจะกรอก RTSP URL ให้อัตโนมัติ ทะลุเครือข่ายข้ามกองร้อยมาให้ทันที

⚠️ ข้อควรระวังขั้นเด็ดขาด

ระบบจะ เอาติ๊กถูกออก จากช่อง "เปิดระบบ AI (Detect)" และ "บันทึกวิดีโอ (Record)" ให้อัตโนมัติ กรุณาอย่าติ๊กกลับเข้าไปเด็ดขาด ให้ใช้สำหรับการดูภาพสดอย่างเดียว มิฉะนั้นระบบส่วนกลางจะสูบภาพเต็มความละเอียดจากกองร้อยตลอด 24 ชั่วโมงจนอินเทอร์เน็ตพังทั้งสองฝั่งครับ

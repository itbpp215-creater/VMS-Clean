BPP-VMS Network Guide

คู่มือเชื่อมต่อ NVR ข้ามกองร้อย

หลักการเชื่อมต่อภาพข้ามหน่วยงาน (Federation)

การดึงภาพจาก NVR ของกองร้อยอื่นมาแสดงผลที่ส่วนกลาง (หรือข้ามกองร้อย) จำเป็นต้องอาศัย เส้นทางเครือข่าย (Network Route) ที่หากันเจอเสียก่อน ระบบ BPP-VMS ออกแบบมาให้รองรับทุกสภาพแวดล้อมเครือข่าย แต่แอดมินเครือข่ายจำเป็นต้องจัดเตรียมเส้นทางให้เหมาะสมกับแต่ละกรณี

กรณีที่ 1: มี Public IP

หน่วยงานปลายทางใช้อินเทอร์เน็ตบ้าน/องค์กร ที่สามารถขอทำ Forward Port จากเร้าเตอร์หลักได้โดยตรง

ความยาก: ⭐

กรณีที่ 2: ไม่มี Public IP

ใช้อินเทอร์เน็ตซิม (4G/5G) หรือเน็ตหอพักที่ติด NAT ไม่สามารถทะลวงจากภายนอกเข้าไปหาเครื่อง NVR ได้

ความยาก: ⭐⭐⭐

กรณีที่ 3: ไม่มี Internet

เป็นโครงข่ายปิดของทหาร/ตำรวจ (Air-gapped) หรืออยู่กลางป่าเขาที่ไม่มีสัญญาณอินเทอร์เน็ตเลย

ความยาก: ⭐⭐⭐⭐⭐

กรณีที่ 1: ปลายทางมี Public IP ง่ายที่สุด

สถานการณ์นี้คือ หน่วยงานปลายทางที่ติดตั้ง NVR ใช้อินเทอร์เน็ตองค์กร หรืออินเทอร์เน็ตบ้าน (เช่น 3BB, TRUE, NT) ที่ได้รับ Public IP (อาจจะแบบ Fix หรือ Dynamic ก็ได้)

1

ตรวจสอบ Public IP ฝั่งปลายทาง

เปิดเบราว์เซอร์ที่เครื่องปลายทางแล้วเข้าเว็บ whatismyip.com หากเลข IP ที่ได้ ตรงกับเลข WAN IP ใน Router แปลว่าคุณได้ Public IP แท้

*หาก IP เป็นแบบไดนามิก (เปลี่ยนทุกครั้งที่เร้าเตอร์รีสตาร์ท) แนะนำให้สมัครและตั้งค่า DDNS (เช่น No-IP, DynDNS) ในเร้าเตอร์ไว้

2

ทำ Port Forwarding ที่ Router ปลายทาง

เข้าไปตั้งค่าใน Router ของหน่วยงานปลายทาง ให้ส่งต่อพอร์ต (Port Forward) เข้ามาหา IP ภายในของเครื่อง BPP-VMS NVR (เช่น 192.168.1.100)

  • พอร์ตที่ต้อง Forward: 80 และ 443 (สำหรับ API และหน้าเว็บ)
  • พอร์ตที่ต้อง Forward: 8555 (โปรโตคอล TCP และ UDP สำหรับดึงภาพสด WebRTC)
3

ทดสอบการเชื่อมต่อจากส่วนกลาง

ที่เครื่องส่วนกลาง ให้ลองเปิดเบราว์เซอร์แล้วพิมพ์: https://<Public-IP-ของปลายทาง> หากขึ้นหน้า Login ของระบบ VMS แสดงว่าสำเร็จ

วิธีแก้ปัญหา (Troubleshooting)

  • เข้าหน้าเว็บไม่ได้: โทรหาผู้ให้บริการเน็ต (ISP) แจ้งว่าขอปลดบล็อกพอร์ต (NAT) สำหรับดูกล้องวงจรปิด บางค่ายจะแจก Private IP (ขึ้นต้นด้วย 100.x.x.x) มาให้โดยปริยาย
  • เข้าเว็บได้แต่ภาพกล้องดำ/ไม่มา: ลืม Forward พอร์ต 8555 (UDP) ทำให้วิดีโอถูกบล็อกโดยไฟร์วอลล์เร้าเตอร์

กรณีที่ 2: ปลายทางไม่มี Public IP ต้องใช้ VPN

สถานการณ์นี้คือ หน่วยงานปลายทางใช้เน็ตซิม (4G/5G Router) หรืออินเทอร์เน็ตที่ติด NAT (Carrier-grade NAT) จากผู้ให้บริการ ซึ่งคนข้างนอกไม่สามารถทะลุเข้ามาได้เลย ต้องให้ฝั่งปลายทาง "มุด" ออกมาหาแทน

1

ติดตั้ง SD-WAN / Virtual LAN (แนะนำ ZeroTier หรือ Tailscale)

เนื่องจาก Forward Port ไม่ได้ เราต้องสร้าง "เครือข่ายจำลองวงเดียวกัน" ขึ้นมา

Tailscale: ลงทะเบียนที่ tailscale.com และติดตั้งโปรแกรม Tailscale ลงบนทั้งเครื่อง NVR ส่วนกลาง และเครื่อง NVR ปลายทางทุุกเครื่อง ล็อกอินด้วยบัญชีเดียวกัน

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
2

ดึง IP เสมือน (VPN IP)

เมื่อเชื่อมต่อสำเร็จ แต่ละเครื่องจะได้ IP ใหม่ที่อยู่ในวงเดียวกัน (เช่น 100.x.x.x สำหรับ Tailscale) คุณจะใช้ IP นี้ในการสื่อสารเสมือนว่าเครื่องตั้งอยู่ติดกันเลย

วิธีแก้ปัญหา (Troubleshooting)

  • Ping หา IP VPN ไม่เจอ: ฝั่งปลายทางเน็ตอาจจะหลุด หรือ Tailscale service หยุดทำงาน ให้ลองสั่ง sudo systemctl restart tailscaled
  • ภาพสะดุดมาก: การใช้ VPN แบบนี้คือการวิ่งผ่าน Relay server (ถ้ายิงตรง P2P ไม่ทะลุ NAT) ทำให้มี Latency สูง เป็นข้อจำกัดของเน็ตซิม ให้อดทน หรือลด Bitrate กล้องฝั่งปลายทางลง

กรณีที่ 3: ไม่ได้เชื่อมต่ออินเทอร์เน็ตเลย Network ระดับฮาร์ดแวร์

สถานการณ์สุดวิสัย เช่น หน่วยงานอยู่กลางป่า (จุดตรวจชายแดน) หรือเป็นโครงข่าย Intranet ภายในของทหาร/ตำรวจ ที่ไม่อนุญาตให้ออกอินเทอร์เน็ตเด็ดขาดเพื่อความปลอดภัยขั้นสูงสุด

1

การเชื่อมต่อทางกายภาพ (Physical Link)

คุณต้องเชื่อมต่อระบบ LAN ของทั้งสองหน่วยงานเข้าหากันทางกายภาพ เลือกวิธีใดวิธีหนึ่ง:

  • 1. ยิงสัญญาณวิทยุ (Wireless Point-to-Point): ใช้เสาจานยิงสัญญาณ (เช่น Ubiquiti airMAX) ยิงข้ามเขาระยะ 5-20 กิโลเมตร ให้อารมณ์เหมือนลากสาย LAN กลางอากาศ
  • 2. ลากสาย Fiber Optic: ลากสายส่วนตัวหากระยะทางไม่ไกลเกินไป
  • 3. ใช้ Leased Line / MPLS ของหน่วยงานรัฐ: ติดต่อศูนย์สารสนเทศตำรวจ/ทหาร เพื่อขอใช้ช่องสัญญาณ Intranet ที่มีอยู่แล้ว ร้องขอให้เขาสร้าง VLAN Route วง IP ของทั้งสองฝั่งเข้าหากัน
2

ตั้งค่า Static Route ที่เร้าเตอร์

หากใช้เครือข่าย MPLS (วิธีที่ 3) แอดมินเครือข่ายต้องทำ Static Route เพื่อให้วง LAN ฝั่งส่วนกลาง รู้จักวิธีวิ่งไปหา วง LAN ฝั่งจุดตรวจชายแดน

ตัวอย่าง: ส่วนกลาง 192.168.1.x ปลายทาง 192.168.2.x

วิธีแก้ปัญหา (Troubleshooting)

  • Ping หา IP ปลายทางไม่เจอ: ส่วนมากเกิดจากติดไฟร์วอลล์บนเร้าเตอร์ระดับองค์กร (Core Switch) ต้องประสานงานฝ่าย IT ของหน่วยงานเพื่ออนุญาตพอร์ต TCP 443 และ UDP 8555 วิ่งข้าม VLAN
  • ถ้าใช้เสายิง Wireless แล้วสัญญาณขาดช่วงฝนตก: ต้นไม้หรือสภาพอากาศอาจบังระยะคลื่น (Line of Sight) ต้องตั้งเสาให้สูงขึ้นหรือปรับช่องสัญญาณ (Channel) ให้กวนกันน้อยที่สุด

ขั้นตอนสุดท้าย: การตั้งค่าดึงภาพใน VMS

เมื่อคุณจัดการเครือข่าย (Network) เรียบร้อยจนเครื่องส่วนกลางสามารถเข้าถึง IP ของเครื่องปลายทางได้แล้ว (ไม่ว่าจะเป็น Public IP, Tailscale IP, หรือ IP ภายใน) ให้ทำตามสเต็ปนี้ที่เครื่องส่วนกลาง

1

เพิ่มข้อมูล Node ปลายทาง

1. ที่หน้า Dashboard ส่วนกลาง กดที่รูปเฟือง "การตั้งค่าระบบ"

2. เลื่อนลงไปที่หัวข้อ "รายชื่อหน่วยงานในเครือข่าย (Federation Nodes)" (หรืออาจต้องแก้ไฟล์ nodes.json โดยตรง ขึ้นอยู่กับเวอร์ชัน)

3. กดปุ่ม "เพิ่มหน่วยงาน" และกรอกข้อมูล:

  • ชื่อหน่วยงาน: เช่น กองร้อย ตชด. 324
  • URL: ใส่ IP ที่คุณหามาได้ เช่น https://100.123.45.67 หรือ https://192.168.2.10

4. สำคัญ: ตรวจสอบรหัสผ่าน WATCHLIST_FEDERATION_SHARED_SECRET ในไฟล์ .env ของทั้งสองเครื่อง ต้องตรงกันเป๊ะ (เช่น `MySecretKey123!`) มิฉะนั้นระบบจะปฏิเสธการเชื่อมต่อ

2

ดึงกล้องมาแสดงผล

1. กลับมาที่แท็บ "กล้องในระบบ (NVR)" และกดปุ่ม "เพิ่มกล้องใหม่"

2. ที่มุมขวา เลือก Dropdown [- หน่วยงานอื่น -] คุณจะเห็น "กองร้อย ตชด. 324" โผล่ขึ้นมา

3. เลือกหน่วยงานนั้น ระบบจะทำการโหลดรายชื่อกล้องจากฝั่งนู้นมาแสดง เลือกกล้องที่ต้องการแล้วกด "ดึงข้อมูล"

4. กดปุ่มบันทึก เป็นอันเสร็จสิ้น! ภาพจะมาแสดงที่หน้าจอรวมทันที

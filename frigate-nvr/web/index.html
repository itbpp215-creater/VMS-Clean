รูปแบบสตรีม (RTSP Stream Syntax) ของ TP-Link VIGI

กล้อง TP-Link VIGI มีความปลอดภัยและเสถียรภาพสูง สามารถดึงสัญญาณภาพสดและบันทึกได้ทั้งแบบรายกล้อง และดึงทุกช่องจากเครื่อง NVR:

🔹 กล้อง VIGI Standalone (ต่อตรงรายตัว):
Main Stream: rtsp://{user}:{pass}@{camera_ip}:554/stream1
Sub Stream: rtsp://{user}:{pass}@{camera_ip}:554/stream2
* {user} และ {pass} คือรหัสผ่านที่ตั้งไว้ในโปรแกรม VIGI Security Manager หรือ VIGI App
🔹 ดึงจากเครื่อง VIGI NVR หลายช่อง (NVR Channel Stream):
หากหน่วยงานมีกล้อง 4, 8, หรือ 16 ตัว ต่อเข้า NVR ตัวเดียว สามารถดึงแต่ละช่องผ่าน IP ของ NVR ได้เลย:
ช่องที่ 1: rtsp://{user}:{pass}@{nvr_ip}:554/ch1/stream2
ช่องที่ 2: rtsp://{user}:{pass}@{nvr_ip}:554/ch2/stream2
... จนถึงช่องสุดท้าย เช่น /ch16/stream2 (แนะนำใช้ stream2 เพื่อความลื่นไหลและไม่เปลืองแบนด์วิดท์)
💡 เทคนิค Zero Server Load (ประหยัดพลังงานเซิร์ฟเวอร์ 100%):
กล้อง VIGI มี AI ตรวจจับคนและยานพาหนะในตัวอยู่แล้ว ในช่อง ประเภทกล้อง (Preset) ให้เลือกเป็น TP-Link VIGI (Smart AI) ระบบจะปิด Server AI บน Frigate ทันที ทำให้ประหยัดสเปกเครื่องเซิร์ฟเวอร์ โดยที่ฟังก์ชันบันทึกย้อนหลัง 24/7 และภาพสดบนหน้าเว็บยังทำงานได้เต็ม 100%

การตั้งค่า Webhook ในกล้อง Dahua ITC / VIGI LPR

ระบบ BPP-VMS รองรับการรับข้อมูลป้ายทะเบียนและภาพถ่ายจากกล้อง LPR โดยตรง ผ่านระบบ Webhook ที่มีความรวดเร็วสูง (< 50ms):

ขั้นตอนที่ 1: คัดลอก Webhook URL ของเซิร์ฟเวอร์ BPP-VMS
* หากเซิร์ฟเวอร์มี Domain หรือ IP ภายนอก ให้เปลี่ยน localhost เป็น IP หรือ Domain ของเซิร์ฟเวอร์
ขั้นตอนที่ 2: ตั้งค่าในหน้า Web UI ของกล้อง Dahua ITC
  1. เปิดเบราว์เซอร์แล้วเข้าสู่ระบบของกล้อง Dahua ITC (เช่น http://192.168.1.108)
  2. ไปที่เมนู Setting > Event > Smart Plan และเปิดใช้งานฟังก์ชัน ITC / ANPR (License Plate Recognition)
  3. ไปที่เมนู Setting > Network > Access Platform > Alarm Center หรือ HTTP Push / Webhook
  4. ทำเครื่องหมายถูกที่ Enable และวาง Webhook URL ที่คัดลอกมาลงในช่อง URL / Server Address
  5. เลือกส่งข้อมูล: Vehicle Picture (ภาพรถ), Plate Picture (ภาพป้าย), และ Plate Info (ข้อความป้ายทะเบียน)
  6. กด Save บันทึกการตั้งค่า
⚡ การประมวลผล Watchlist อัตโนมัติ:
เมื่อกล้องตรวจจับป้ายทะเบียนได้ กล้องจะยิงข้อมูลตรงมาที่ Webhook นี้ BPP-VMS จะนำป้ายไปเทียบกับฐานข้อมูลรถเฝ้าระวัง (Watchlist) หากตรงกับแบล็กลิสต์ ระบบจะส่งการแจ้งเตือนพร้อมรูปถ่ายเข้า Telegram ของเจ้าหน้าที่ทันที โดยไม่ต้องเปิด Server AI บน Frigate

วิธีเชื่อมต่อหน่วยงานภายนอกที่ไม่มี Public IP (CGNAT / ซิมมือถือ 4G)

กรณีหน่วยงานภายนอก (เช่น โรงเรียน, ด่านชุมชน, อบต.) มีกล้อง VIGI หลายตัว และไม่มี Public IP หรือเป็นเน็ตซิม 4G ไม่สามารถ Forward Port หรือติดตั้ง MikroTik ได้ มี 2 ทางเลือกที่ทำได้ทันที 100%:

โปรแกรมสำเร็จรูป BPP NVR Bridge สำหรับ Windows
โปรแกรมหน้าต่างกราฟิกพร้อมใช้งานในตัว ไม่ต้องลง Python หรือ Node.js ย่อลง System Tray ได้
ดาวน์โหลด BPP NVR Bridge (ZIP) ⚡ อัปเดตสคริปต์ (PS1) 📖 คู่มือเว็บ (หมวด 7)
วิธีใช้งาน: แตกไฟล์ ZIP > ดับเบิลคลิกเปิด BPP-NVR-Bridge.vbs (หรือ .bat) > กรอก IP NVR (กรณีผ่านท่อ VPN ใช้ 10.10.10.2:554) และเลือกช่องกล้อง > กด "🚀 เริ่มส่งสัญญาณ" ระบบจะส่งสัญญาณ RTMP Outbound ตรงเข้าสู่ BPP-VMS ทันที
ทางเลือกที่ 1: กล้องหรือ NVR ผลักสัญญาณออก (RTMP Outbound Push)
ไฟร์วอลล์และเน็ต 4G จะบล็อกเฉพาะการเชื่อมต่อขาเข้า (Inbound) แต่จะอนุญาตการส่งออก (Outbound) เสมอ:
เป้าหมาย RTMP: rtmp://[SERVER_IP]:1935/live/[stream_key]
กล้องหรือเครื่อง NVR ที่รองรับ RTMP Push สามารถใส่ URL นี้เพื่อส่งภาพสดเข้ามาที่ BPP-VMS ได้โดยตรงโดยไม่ต้องมีเราเตอร์ MikroTik
ทางเลือกที่ 2: ใช้คอมพิวเตอร์หน้างานเป็นตัวบริดจ์ (BPP NVR Bridge — รองรับ VIGI / Dahua / Hikvision)
หากเครื่อง NVR หรือกล้องไม่มีเมนู RTMP Push ให้ใช้คอมพิวเตอร์ในวง LAN เดียวกับกล้องเปิดโปรแกรม BPP NVR Bridge ทำหน้าที่แปลงสัญญาณ RTSP ยี่ห้อ VIGI, Dahua, Hikvision หรือ Custom URL ส่งตรงเข้าสู่เซิร์ฟเวอร์ BPP-VMS อัตโนมัติ (กิน CPU ~0% ไม่กระตุก)
# ตัวอย่างคำสั่ง Bridge ที่โปรแกรมรันเบื้องหลัง (Stream Copy):
ffmpeg -rtsp_transport tcp -re -i "rtsp://admin:pass@192.168.1.100:554/ch1/stream2" -c copy -f flv "rtmp://[SERVER_IP]:1935/live/[unit_code]_ch1"
ขั้นตอนฝั่งเซิร์ฟเวอร์: การลงทะเบียนกล้อง Bridge เข้า Dashboard (สำหรับผู้ดูแลระบบ)
หลังจากฝั่งหน้างานกด "🚀 เริ่มส่งสัญญาณ (Start Bridge)" ให้ผู้ดูแลระบบเพิ่มกล้องในระบบ BPP-VMS ดังนี้:
  1. ไปที่เมนู ⚙️ ตั้งค่าระบบ ➔ แท็บ กล้องในระบบ (NVR) ➔ คลิก "+ เพิ่มกล้องใหม่"
  2. ประเภทกล้อง (Preset): เลือก TP-Link VIGI (Smart AI) เพื่อปิด Server AI (ประหยัด CPU 100%)
  3. ชื่อกล้อง: ตั้งตามรหัสหน่วยงานและช่อง เช่น dan_khok_sung_ch1
  4. RTSP URL (Main Stream): กรอก URL สตรีม RTMP ภายในเครื่อง:
    rtmp://127.0.0.1:1935/live/[unit_code]_ch[N]  (เช่น rtmp://127.0.0.1:1935/live/dan_khok_sung_ch1)
  5. คลิก "บันทึก" ภาพสดจากหน่วยงานภายนอกจะปรากฏบน Dashboard ทันที
🛡️ ข้อกำหนดและการตั้งค่าไฟร์วอลล์ (Firewall & Network Guide)
เปิดคู่มือฉบับเต็ม (Master Guide)
• ฝั่งหน้างาน (Bridge): Windows Firewall ต้องอนุญาตการเชื่อมต่อ Outbound Port 1935 (RTMP) ไปยังเซิร์ฟเวอร์
• ฝั่งเซิร์ฟเวอร์ (BPP-VMS): ต้องเปิดรับ Inbound Port 1935 (RTMP) ใน Router/Firewall ของศูนย์สั่งการ
🖥️ 1. ฝั่งหน้างาน (Bridge Client) — ปลดบล็อค Windows Firewall (Outbound 1935)
วิธีที่ 1: รันคำสั่งด่วนใน PowerShell (Run as Administrator) 
New-NetFirewallRule -DisplayName "BPP-VMS RTMP Outbound" -Direction Outbound -LocalPort 1935 -Protocol TCP -Action Allow
วิธีที่ 2: ตั้งค่าผ่านหน้าต่าง GUI:
  1. เปิด Windows Defender Firewall with Advanced Security
  2. คลิก Outbound Rules (แถบซ้าย) ➔ คลิก New Rule... (แถบขวา)
  3. เลือก Port ➔ TCP ➔ กรอก Specific remote ports: 1935
  4. เลือก Allow the connection ➔ กด Next จนถึงหน้าสุดท้าย ตั้งชื่อ BPP-VMS RTMP แล้วกด Finish
🏢 2. ฝั่งเซิร์ฟเวอร์ศูนย์ (BPP-VMS) — ตั้งค่า Forward พอร์ต 1935 (Inbound)
กรณีที่ 1: ศูนย์ใช้เราเตอร์ MikroTik (เสียบสายด่วนใน Terminal) 
/ip firewall nat add chain=dstnat dst-port=1935 action=dst-nat protocol=tcp to-addresses=[IP_BPP_VMS_SERVER] to-ports=1935 comment="BPP-VMS RTMP 1935"
*เปลี่ยน [IP_BPP_VMS_SERVER] เป็น IP เครื่องเซิร์ฟเวอร์ เช่น 192.168.1.50
กรณีที่ 2: ศูนย์ใช้เราเตอร์ทั่วไปของผู้ให้บริการ (AIS Fibre / True / 3BB):
เข้าหน้าตั้งค่าเราเตอร์ ➔ หาเมนู Port Forwarding / Virtual Server ➔ เพิ่มกฎใหม่: External Port: 1935, Internal Port: 1935, Protocol: TCP, Internal IP: IP เครื่อง BPP-VMS Docker
กรณีที่ 3: ศูนย์ไม่มี Public IP (ติด CGNAT):
ให้ติดตั้ง Tailscale หรือ ZeroTier ทั้งเครื่อง Bridge หน้างานและเครื่อง BPP-VMS Server เพื่อจำลองวงแลนเสมือน (VPN Mesh) และยิงสตรีม RTMP ผ่าน IP ของ VPN โดยไม่ต้องเปิดพอร์ตที่เร้าเตอร์
🔐 3. การเข้ารหัสรหัสผ่านกล้องอัตโนมัติ (URL-encoding สำหรับ @, $, :, #)

ระบบ BPP-VMS Dashboard รุ่นใหม่จะทำการ URL-encoding ให้อัตโนมัติ หากรหัสผ่านของกล้องหรือ NVR มีอักขระพิเศษ ป้องกันปัญหาสตรีม RTSP/RTMP ไม่ขึ้น โดยแปลงตามมาตรฐานดังนี้:

อักขระพิเศษURL-encodedตัวอย่าง
@%40pass@123 ➔ pass%40123
#%23bpp#215 ➔ bpp%23215
$%24admin$99 ➔ admin%2499
:%3Asec:ret ➔ sec%3Aret
✅ ข้อดีเด่นชัด:
ประหยัดงบประมาณ ไม่ต้องจัดซื้อเราเตอร์ MikroTik เพิ่มเติม และไม่กระทบโครงสร้างระบบเครือข่ายเดิมของหน่วยงานนั้น รองรับ NVR ยี่ห้อชั้นนำทั้ง VIGI, Dahua, Hikvision สามารถนำเข้ากล้องนับสิบตัวสู่ศูนย์สั่งการ BPP-VMS ได้อย่างง่ายดายและปลอดภัย
NVR Auto-Discovery Wizard
ค้นหาและเพิ่มกล้องจาก NVR เครือข่ายเข้าสู่ระบบอัตโนมัติ (รองรับสูงสุด 64 ช่อง)
💡 คำแนะนำการใช้งาน Wizard ค้นหากล้องอัตโนมัติ:
  • IP Address: ใส่ IP ของเครื่อง NVR ในวง LAN เช่น 192.168.1.100 หรือ Public IP / DDNS หากเชื่อมต่อข้ามไซต์
  • RTSP Port: ค่ามาตรฐานคือ 554 (ไม่ต้องเปลี่ยนหากไม่ได้แก้ไขพอร์ตใน NVR)
  • Username / Password: ใส่ชื่อผู้ใช้และรหัสผ่านของ เครื่อง NVR (ไม่ใช่รหัสเข้า BPP-VMS)
  • ยี่ห้อ (Brand): เลือกยี่ห้อ NVR ให้ตรง เพื่อให้ระบบเรียกใช้เส้นทาง RTSP สตรีมที่ถูกต้อง (VIGI, Dahua, Hikvision)
  • การทำงาน: ระบบจะใช้ Socket ตรวจสอบการตอบสนองของช่องสัญญาณ 1-64 หากพบสัญญาณจะแสดงในรายการให้เลือกเพื่อนำเข้าอัตโนมัติทันที

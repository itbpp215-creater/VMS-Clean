# 🛰️ คู่มือการใช้งานโปรแกรม BPP NVR Bridge (ฉบับหน้างาน)

โปรแกรม **BPP NVR Bridge** ออกแบบมาเพื่อให้หน่วยงานภายนอก (ด่านตรวจ, โรงเรียน, อบต., สภ.) ที่มีเครื่องบันทึก NVR หรือกล้อง **TP-Link VIGI, Dahua, Hikvision หรือยี่ห้ออื่นๆ** สามารถส่งภาพสดเข้าสู่ศูนย์บัญชาการ **BPP-VMS** ได้ทันที **แม้ไม่มี Public IP หรือเป็นเน็ตซิม 4G (ติด CGNAT) โดยไม่ต้องซื้อเราเตอร์ MikroTik เพิ่มเติม**

---

## ⚠️ สิ่งที่ต้องตรวจสอบก่อนใช้งาน (Pre-flight Checklist)

1. **การเชื่อมต่อเครือข่าย:** เครื่องคอมพิวเตอร์ที่รัน Bridge ต้องอยู่ในวง LAN เดียวกับ NVR และสามารถออกอินเทอร์เน็ตได้
2. **ไฟร์วอลล์ (Windows Firewall):** ไฟร์วอลล์ฝั่งหน้างานต้องอนุญาตการเชื่อมต่อขาออก (Outbound) ไปยังเซิร์ฟเวอร์ BPP-VMS ที่พอร์ต **`1935` (RTMP)** และพอร์ต **`554` (RTSP)** ในวง LAN
3. **โฟลเดอร์โปรแกรม:** ต้องคงโฟลเดอร์ **`bin\ffmpeg.exe`** ไว้คู่กับโปรแกรมเสมอ ห้ามลบหรือย้ายไฟล์
4. **สิทธิ์ NVR:** บัญชี Username/Password ของเครื่อง NVR ต้องมีสิทธิ์ดึงภาพสด (Live View)

---

## ⚡ ขั้นตอนการใช้งาน 4 ขั้นตอน

### ขั้นตอนที่ 1: แตกไฟล์ ZIP และเปิดโปรแกรม
1. แตกไฟล์ `bpp-nvr-bridge.zip` ไว้ที่โฟลเดอร์ใดก็ได้บนคอมพิวเตอร์ (เช่น `C:\BPP-NVR-Bridge` หรือ `Desktop`)
2. ตรวจสอบว่ามีโฟลเดอร์ `bin` และมีไฟล์ `ffmpeg.exe` อยู่ภายใน
3. ดับเบิลคลิกเปิดไฟล์ **`BPP-NVR-Bridge.vbs`** *(แนะนำอย่างยิ่ง เพื่อเปิดแบบไม่มีหน้าต่างคอนโซลดำขึ้นมารบกวน 100%)* หรือเปิดผ่าน **`BPP-NVR-Bridge.bat`**

### ขั้นตอนที่ 2: กรอกข้อมูลการเชื่อมต่อ
1. **ช่องที่ 1 (เซิร์ฟเวอร์ปลายทาง BPP-VMS Gateway):**
   * **IP/Domain เซิร์ฟเวอร์:** ระบุ **`bpp215.duckdns.org`** หรือ WAN Public IP ของศูนย์ *(เนื่องจากสัญญาณภาพวิ่งผ่านพอร์ต RTMP `1935` จึงต้องชี้ตรงมาที่เราเตอร์ที่ทำ Forward Port ไว้ ห้ามใช้ `vms.local` ในช่องนี้เพราะ Cloudflare Proxy ปิดกั้นพอร์ต 1935)*
   * **รหัสหน่วยงาน (Unit Code):** ตั้งชื่อย่อภาษาอังกฤษของหน่วยงาน เช่น `Bpp215`, `dan_khok_sung`, `sch_ban_dan` *(ห้ามมีเว้นวรรคและอักขระพิเศษ)*
2. **ช่องที่ 2 (เครื่อง NVR หน้างาน):**
   * **ยี่ห้อ NVR:** เลือกยี่ห้อของเครื่องบันทึก:
     * **`TP-Link VIGI`** — รูปแบบมาตรฐาน `/ch{ch}/stream1|stream2`
     * **`Dahua / DH`** — รูปแบบ `/cam/realmonitor?channel={ch}&subtype=0|1`
     * **`Hikvision / HIK`** — รูปแบบ `/Streaming/Channels/{ch}01|02`
     * **`กำหนดเอง (Custom URL)`** — ใส่ RTSP Path template เองได้ เช่น `/live/ch{ch}`
   * **NVR IP / Port:**
     * **กรณีต่อตรงในวง LAN หน้างาน:** ใส่ IP ของเครื่อง NVR เช่น `192.168.1.100` หรือ `192.168.20.199`
     * **กรณีเชื่อมต่อผ่านท่อ VPN (เช่น MikroTik WireGuard `10.10.10.x`):** ให้ใส่ IP ปลายท่อของ MikroTik เช่น **`10.10.10.2`** และ Port **`554`** ได้ทันที เนื่องจากเราเตอร์ MikroTik มีการทำ Port Forward (DST-NAT) พอร์ต 554 ไปยัง NVR ให้แล้ว (ไม่ต้องกรอก IP วงใน 192.168.20.199)
   * **User / Pass:** ใส่ชื่อผู้ใช้และรหัสผ่านของเครื่อง NVR
   * คลิกปุ่ม **"ทดสอบเชื่อมต่อ"** เพื่อตรวจเช็กการเชื่อมต่อไปยัง NVR
3. **ช่องที่ 3 (เลือกช่องสัญญาณกล้อง):**
   * ติ๊กเครื่องหมายถูก [✓] ที่ช่องกล้องที่ต้องการส่งภาพ (รองรับสูงสุด 16 ช่อง)
   * เลือกความละเอียด:
     * **Sub Stream:** แนะนำเป็นค่าเริ่มต้น (กินเน็ตน้อยมาก 0% CPU ลื่นไหลไม่กระตุก)
     * **Main Stream:** คมชัดสูงสุด (สำหรับช่องที่ต้องการความละเอียดสูงเป็นพิเศษ)

### ขั้นตอนที่ 3: กดเริ่มทำงาน (Start Bridge)
1. คลิกปุ่ม **"💾 บันทึกค่า"**
2. คลิกปุ่ม **"🚀 เริ่มส่งสัญญาณ (Start Bridge)"**
   * สัญลักษณ์จะเปลี่ยนเป็น **🟢 ออนไลน์** สำหรับช่องที่ส่งภาพสำเร็จ
3. **การตั้งค่าเสริม (แนะนำอย่างยิ่ง):**
   * ติ๊กถูก [✓] **"เริ่มส่งสัญญาณอัตโนมัติเมื่อเปิดโปรแกรมนี้"**
   * ติ๊กถูก [✓] **"เปิดโปรแกรมพร้อมเปิดเครื่อง (Run on Windows Startup)"**
     *(เมื่อรีสตาร์ทคอมพิวเตอร์ โปรแกรมจะเปิดตัวเองและเริ่มส่งสัญญาณให้อัตโนมัติทันที)*
4. คลิกปุ่ม **"📥 ย่อลง System Tray"** โปรแกรมจะย่อไปอยู่ข้างนาฬิกาที่มุมขวาล่างของจอ ไม่เกะกะการทำงาน

### ขั้นตอนที่ 4: ลงทะเบียนกล้องที่เซิร์ฟเวอร์ (สำหรับผู้ดูแลระบบ BPP-VMS)
> ⚠️ **ขั้นตอนนี้ทำที่ฝั่งเซิร์ฟเวอร์ BPP-VMS เท่านั้น** (โดยผู้ดูแลระบบ):

หลังจากฝั่งหน้างานเริ่มส่งสัญญาณ Bridge แล้ว สัญญาณจะยิงเข้าสู่พอร์ต RTMP `1935` ของเซิร์ฟเวอร์ ให้ดำเนินการนำกล้องเข้า Dashboard:
1. เปิดหน้าเว็บ **BPP-VMS Dashboard** เข้าสู่ระบบด้วยสิทธิ์ Admin
2. ไปที่เมนู **⚙️ ตั้งค่าระบบ** ➔ แท็บ **กล้องในระบบ (NVR)** ➔ คลิก **"+ เพิ่มกล้องใหม่"**
3. กรอกข้อมูลกล้อง:
   * **ชื่อกล้อง (Camera Name):** ตั้งชื่อตามรหัสหน่วยงานและช่อง เช่น `dan_khok_sung_ch1`
   * **ประเภทกล้อง (Preset):** เลือก **`TP-Link VIGI (Smart AI)`** *(เพื่อปิด AI ตรวจจับบนเซิร์ฟเวอร์ ประหยัด CPU 100%)*
   * **RTSP URL (Main Stream):** กรอก URL สตรีม RTMP:
     ```
     rtmp://127.0.0.1:1935/live/[UNIT_CODE]_ch[N]
     ```
     *(ตัวอย่าง: `rtmp://127.0.0.1:1935/live/dan_khok_sung_ch1`)*
4. กด **"บันทึก"** กล้องจะแสดงภาพสดบนหน้าจอหลักของ BPP-VMS ทันที

---

## 🛡️ ระบบเฝ้าระวังอัตโนมัติ (Watchdog Auto-Healing)
* หากอินเทอร์เน็ตหลุด ไฟตก หรือเครื่อง NVR ดับชั่วคราว ตัวโปรแกรมจะไม่ปิดตัวเอง
* โปรแกรมจะตรวจจับและวนลูปพยายามเชื่อมต่อใหม่ให้อัตโนมัติทุก 5 วินาที ทันทีที่เน็ตกลับมา ภาพจะกลับมาขึ้นที่ศูนย์สั่งการทันที

| อาการที่พบ | สาเหตุที่เป็นไปได้ | วิธีแก้ไข |
|---|---|---|
| **เปิดโปรแกรมแล้วขึ้นเตือน "ไม่พบโปรแกรม FFmpeg"** | ไฟล์ `bin\ffmpeg.exe` หาย หรือแตกไฟล์ไม่ครบ | แตกไฟล์ `bpp-nvr-bridge.zip` ใหม่อีกครั้ง และตรวจสอบว่ามีโฟลเดอร์ `bin` ที่มี `ffmpeg.exe` อยู่ |
| **กดเริ่มแล้วสถานะขึ้น 🔴 ผิดพลาด ทุกช่อง** | IP NVR, Port, User หรือ Password ผิด / ยี่ห้อ NVR ไม่ตรง | 1. กดปุ่ม "ทดสอบเชื่อมต่อ" เพื่อตรวจ IP/Port<br>2. ตรวจสอบ User/Password ในหน้า NVR<br>3. ตรวจสอบว่าเลือก "ยี่ห้อ NVR" ตรงกับรุ่นเครื่อง |
| **สถานะขึ้น 🟡 กำลังเชื่อมใหม่ ตลอดเวลา** | ส่ง RTMP ออกไปยังเซิร์ฟเวอร์ไม่ได้ (เน็ตหลุด / Firewall บล็อก) | 1. ตรวจสอบว่าคอมพิวเตอร์ออกเน็ตได้หรือไม่<br>2. ตรวจสอบ IP/Domain เซิร์ฟเวอร์ในช่องที่ 1<br>3. ตรวจสอบว่าไฟร์วอลล์ไม่ได้บล็อก Outbound port 1935 |
| **Bridge ออนไลน์แล้ว แต่ภาพไม่ขึ้นใน Dashboard** | ยังไม่ได้ลงทะเบียนกล้องฝั่งเซิร์ฟเวอร์ | ดำเนินการตาม **ขั้นตอนที่ 4** ในคู่มือนี้ โดยระบุ Stream URL ให้ตรงกับ `unit_code` และเลขช่อง |
| **ยี่ห้อ NVR ไม่อยู่ในรายการตัวเลือก** | เป็นกล้องหรือ NVR แบรนด์เฉพาะ | เลือกยี่ห้อเป็น **"กำหนดเอง (Custom URL)"** แล้วระบุ RTSP Path template ของแบรนด์นั้น โดยใส่ `{ch}` แทนเลขช่อง |

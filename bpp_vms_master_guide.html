⚠️ หากพบข้อผิดพลาด PSSecurityException (cannot be loaded because running scripts is disabled):

เกิดจากนโยบายความปลอดภัยเริ่มต้นของ Windows PowerShell บล็อกไม่ให้รันสคริปต์ .ps1 ให้แก้ไขโดยพิมพ์คำสั่งด้านล่างนี้ใน PowerShell:

*เมื่อระบบขึ้นข้อความให้ยืนยัน ให้พิมพ์ Y (Yes) หรือ A (Yes to All) แล้วกด Enter จากนั้นทดสอบรัน npm -v อีกครั้ง

1. 🔬 Expression Anatomy Map (ผ่าพิสูจน์โค้ดสูตรดูดค่าทีละชิ้น)

ใน n8n การดึงข้อมูลจากโหนดก่อนหน้าจะใช้สูตรที่เรียกว่า Expression (โหมดดูดค่าสด) ลองดูตัวอย่างคำสั่ง ={{ $json.body.type || 'chat' }} ว่าประกอบด้วยอะไรบ้าง (เปรียบเหมือนการเปิดกล่องพัสดุซ้อนกัน 3 ชั้น):

={{ $json.body.type || 'chat' }} ▲ ▲ ▲ ▲ ▲ ▲ │ │ │ │ │ │ │ │ │ │ │ └─ ค่าสำรองกันพัง (Fallback Value) │ │ │ │ │ ถ้าหาข้อมูล 3 กล่องแรกไม่เจอเลย ให้ใช้คำว่า 'chat' แทน (ระบบจะได้ไม่ล่ม) │ │ │ │ └─ เครื่องหมาย OR (หรือ) │ │ │ └─ เปิดกล่องชั้นในสุด (Field Name) ดึงชื่อประเภทข้อความออกมา │ │ └─ เปิดกล่องชั้นกลาง (Nested Object) เจาะเข้าไปในเนื้อหา (body) │ └─ กล่องพัสดุใบใหญ่ (Current Item JSON) ข้อมูลทั้งหมดที่ไหลมาจากโหนดก่อนหน้า └─ เปิด/ปิด โหมดสูตร (Expression Delimiters) บอกบอทว่านี่ไม่ใช่ข้อความธรรมดา แต่เป็นคำสั่งให้ไปดูดข้อมูลมาโชว์

5. ❓ ปัญหาที่พบบ่อย (Troubleshooting FAQ)

❌ อาการที่เจอ (ปัญหา) 🔍 สาเหตุ ✅ วิธีแก้
1. Switch ไม่ยอมแยกสาย ข้อมูลไม่ไหลไปไหนเลย (ค้าง) ช่อง Mode ของโหนด Switch ยังเป็นค่าเดิม (Expression) ไม่ได้เปลี่ยนเป็นแบบตั้งกฎ (Rules) ในหน้าต่าง Switch ให้เปลี่ยนช่องแรกสุด Mode เป็น `Rules`
2. สูตร Expression ขึ้นตัวอักษรสีแดงเตือนว่า Invalid พิมพ์วงเล็บปีกกาผิด หรือลืมใส่เครื่องหมายเท่ากับ (=) นำหน้าสูตร ลบแล้วพิมพ์ใหม่ให้ถูกต้องเป็น ={{ }} ห้ามเว้นวรรคระหว่างปีกกา
3. ต่อสายเสร็จหมดแล้ว แต่โหนดปลายทางบอกว่าไม่ได้รับข้อมูล คุณลากสายออกจากจุด Output หมุดผิดเบอร์ (เช่น ต้องลากจากหมุดบนสุด 0 แต่ไปลากหมุดกลาง 1 แทน) ลบสายเดิม (เอาเมาส์ชี้ที่สายแล้วกดรูปถังขยะ) แล้วลากใหม่จากจุด Output ขา 0 (บนสุด)

HTTP Method

                    POST
                    
🔴 จุดตาย

                  		
                  โปรโตคอลการรับส่งข้อมูลผ่าน HTTP แบบส่งก้อนข้อมูลใน Request Body
                  ต้องส่งข้อมูลขนาดใหญ่ เช่น ภาพถ่าย Base64, พิกัด GPS, รายชื่อผู้ต้องสงสัย ซึ่งส่งผ่าน URL แบบ GET ไม่ได้
                  รับข้อมูลขนาดใหญ่ได้ไม่จำกัด ข้อมูลปลอดภัยไม่หลุดโชว์ใน URL Log
                

                

                  
                    
Path

                    bpp-vms-master
                    
🔴 จุดตาย

                  		
                  ชื่อเส้นทางต่อท้าย URL (Endpoint Slug) สำหรับชี้เป้ามายัง Workflow นี้
                  กำหนด URL เฉพาะของบอท BPP-VMS กลาง ไม่ให้ชนกับ Webhook อื่นในเซิร์ฟเวอร์
                  ได้ URL ชัดเจน .../webhook/bpp-vms-master ชี้ตรงเข้าสู่ระบบ 100%
                

                

                  
                    
Authentication

                    None (หรือ Header Auth)
                    
🟡 ค่าทางเลือก

                  		
                  ระบบตรวจสอบสิทธิ์และกุญแจความปลอดภัยก่อนยอมให้ข้อมูลผ่านเข้ามา
                  ในวงปิด Docker ใช้ None เพื่อความรวดเร็ว หากเปิดสู่ Public ควรเปิด Header Auth ดักตรวจ Secret Key
                  ยืดหยุ่นตามสภาพแวดล้อม ป้องกันคนภายนอกยิง Flood รบกวนระบบ
                

                

                  
                    
Response Mode

                    Using 'Respond to Webhook' Node
                    
🔴 จุดตาย

                  		
                  สั่งให้ n8n ระงับการตอบกลับไว้ก่อน จนกว่าจะรันไปถึงโหนด Respond ปลายทาง
                  ต้องรอให้ AI Agent สกัดข้อความ หรือโค้ดดึง GPS ภาพถ่ายเสร็จก่อน (ใช้เวลา 1-3 วินาที)
                  ผู้เรียก (Dashboard/แอป) ได้รับผลลัพธ์ JSON ที่ AI วิเคราะห์เสร็จในรอบเดียว ไม่ต้อง Polling ซ้ำ

🟢 ประสิทธิภาพ

                    Rules
                    
🔴 จุดตาย

                  		
                  โหมดคัดแยกเส้นทางข้อมูลตามเงื่อนไขตรรกะแบบหลายทางเลือก
                  ทำหน้าที่เป็นชุมสายคัดแยกประเภทงาน เพื่อกระจายงานไปยังโหนดที่เชี่ยวชาญเฉพาะด้าน
                  จุดรับเข้ามีบานเดียว (Single Endpoint) แต่แยกงาน 3 สายได้อย่างเป็นระเบียบ
                

                

                  
                    
Value 1

                    ={{ $json.body.type || 'chat' }}
                    
🔴 จุดตาย

                  		
                  ตัวแปรหลักที่ใช้เปรียบเทียบ โดยอ่านฟิลด์ type จาก Request พร้อมใส่ค่าสำรอง 'chat'
                  ป้องกันกรณีแอปหน้าบ้านลืมส่งฟิลด์ type มา ระบบจะอนุโลมให้เป็นแชทคุยกับ AI ทันที
                  Workflow ไม่ตายกลางทาง (Fail-safe) ทุกข้อความได้รับการประมวลผลแน่นอน
                

                

                  
                    
Rule 0 (chat)

                    Output 0 ➔ AI Agent
                    
🟢 สถาปัตยกรรม

                  		
                  ถ้า type เป็น 'chat' ส่งข้อมูลออกพอร์ตที่ 0
                  ส่งข้อความรายงานเหตุการณ์เข้าสู่โหนด LangChain AI Agent
                  ข้อความได้รับการสกัด Entity ไม่ส่งไปประมวลผลรูปให้เสียเวลา
                

                

                  
                    
Rule 1 (photo)

                    Output 1 ➔ Photo Code
                    
🟢 สถาปัตยกรรม

                  		
                  ถ้า type เป็น 'photo' ส่งข้อมูลออกพอร์ตที่ 1
                  ส่งชุดภาพถ่ายของกลางเข้าสู่โหนดสกัด EXIF GPS
                  ได้พิกัดแผนที่ละติจูด/ลองจิจูดใน 2 มิลลิวินาที ไม่เปลือง Token AI
                

                

                  
                    
Rule 2 (alert)

                    Output 2 ➔ LPR Formatter
                    
🟢 สถาปัตยกรรม

                  		
                  ถ้า type เป็น 'alert' ส่งข้อมูลออกพอร์ตที่ 2
                  ส่งข้อมูลทะเบียนรถจากกล้อง LPR เข้าโหนดจัดรูปแบบการ์ด
                  แจ้งเตือนด่วนเข้า Telegram เจ้าหน้าที่สายตรวจทันที Real-time

const body = $input.item.json.body || {};
const images = Array.isArray(body.images) ? body.images : (body.image_base64 ? [body.image_base64] : []);
const metadataList = Array.isArray(body.metadata_list) ? body.metadata_list : [body.metadata || {}];

// Aggregate GPS and Evidence from all uploaded photos in the batch
let primaryGps = { lat: 13.6892, lng: 99.8214 };
for (const meta of metadataList) {
  if (meta && meta.gps && meta.gps.lat && meta.gps.lng) {
    primaryGps = meta.gps;
    break;
  }
}

const dossierId = 'CASE-' + new Date().toISOString().slice(0,10).replace(/-/g,'') + '-' + Math.floor(1000 + Math.random() * 9000);

return {
  json: {
    status: 'success',
    type: 'batch_photos_processed',
    dossier_id: dossierId,
    total_images_processed: images.length || 1,
    gps: primaryGps,

    sync_targets: {

อธิบายละเอียดยิบทุกบรรทัด ทุกคำศัพท์ ทุกตัวแปร และผลกระทบเชิงระบบหากไม่เขียนตามนี้

            

          


          

            
            
            

              

                📌 หมวดที่ 1: การดึงข้อมูล JSON จากโหนดก่อนหน้า (Data Ingress)
              

              

                const body = $input.item.json.body || {};
              

              
    
                
  • const: คำสั่งสร้างกล่องเก็บข้อมูลแบบ "ค่าคงที่" ห้ามโค้ดบรรทัดอื่นมาเขียนทับ ปลอดภัยสูงสุด
    • 
                
  • $input.item.json: วัตถุ Built-in ของ n8n เพื่อเข้าถึงก้อนข้อมูล JSON แถวปัจจุบันที่ส่งมาจากโหนดก่อนหน้า
    • 
                
  • .body: เปิดเข้าไปในคีย์ย่อยชื่อ body ซึ่งบรรจุเนื้อหาที่ Webhook ของกล้องส่งมา
    • 
                
  • || {} (เสื้อชูชีพกันระบบล่ม): ทำไมต้องเขียน? หาก Webhook ส่งข้อมูลว่างเปล่ามา การใส่ || {} จะเปลี่ยนค่า undefined ให้เป็นออบเจกต์ว่างเปล่า {} ทันที หากไม่ใส่ โค้ดบรรทัดต่อไปที่เรียก body.plate จะเกิดข้อผิดพลาดรุนแรง TypeError: Cannot read properties of undefined ทำให้บอทหยุดทำงานทันที!
    • 
              

            


            
            

              

                📌 หมวดที่ 2: สกัดฟิลด์ข้อมูลสำคัญ 7 ตัวแปร พร้อมค่าสำรอง (Extraction & Fallbacks)
              

              

                ทำไมต้องแยกเป็น 7 บรรทัดและมี || 'ค่าเริ่มต้น' ทุกบรรทัด?
              

              

                

                  
const plate = body.plate || '1กข 4567';

                  
• สกัดเลขทะเบียนรถ ถ้าอ่านไม่ทัน/ไม่มีค่า ให้ใช้ค่าจำลองเพื่อทดสอบรันใน n8n ได้ทันที

                

                

                  
const province = body.province || 'สุรินทร์';

                  
• สกัดชื่อจังหวัด ป้องกันการแสดงผลเป็นคำว่า undefined บนหน้าจอเจ้าหน้าที่

                

                

                  
const camera = body.camera_name || body.camera || body.camera_group || body.group || '...';

                  
• ตรวจจับชื่อกล้อง & กลุ่มกล้องอัตโนมัติ: ตรวจหาชื่อกล้องภาษาไทย (camera_name หรือ camera) ก่อนเป็นอันดับแรก หากไม่มี ให้สลับไปดึงชื่อกลุ่มกล้อง (camera_group หรือ group) แทน เพื่อให้ศูนย์สั่งการทราบโซนเกิดเหตุเสมอ ป้องกันค่าว่าง

                

                

                  
const timestamp = body.timestamp || new Date().toLocaleString(...);

                  
• คำศัพท์สำคัญ: new Date().toLocaleString('th-TH', { timeZone: 'Asia/Bangkok' }) บังคับเวลาไทย UTC+7 ป้องกันเวลาบอทช้ากว่าเวลาจริง 7 ชม. จาก Docker Server

                

                

                  
const dangerLevel = body.danger_level || '🔴 อันตรายสูง...';

                  
• สกัดระดับความอันตรายพร้อมไอคอนสี เพื่อให้เห็นระดับภัยคุกคามทันทีจาก Lock Screen

                

                

                  
const eventId = body.event_id || 'ev-lpr-992140';

                  
• สกัดรหัสอ้างอิงเหตุการณ์ (UUID / Primary Key) สำหรับค้นหาแฟ้มคดีและคลิปย้อนหลัง

                

              

            


            
            

              

                📌 หมวดที่ 3: การสร้างลิงก์คลิปวิดีโอเหตุการณ์ย้อนหลัง (Deep Link Construction)
              

              

                const serverHost = 'vms.bpp215.police.go.th';

                const clipUrl = `https://${serverHost}/clip.html?id=${eventId}&cam=${encodeURIComponent(camera)}&type=lpr`;
              

              
    
                
  • serverHost: แยกโดเมนแม่ข่ายออกมา เพื่อให้แก้ไขง่ายในจุดเดียวเมื่อเปลี่ยน IP/Domain
    • 
                
  • เครื่องหมาย Backtick `...` & ${...}: แม่พิมพ์ข้อความเชื่อมตัวแปรโดยไม่ต้องใช้เครื่องหมายบวก + ให้ตาลาย
    • 
                
  • encodeURIComponent(camera): ทำไมต้องมี? ตัวแปร camera มีภาษาไทยและช่องว่าง หากใส่เข้าไปใน URL ตรงๆ ลิงก์จะขาดและกดเปิดวิดีโอบนสมาร์ตโฟนไม่ติด ฟังก์ชันนี้จะแปลงภาษาไทยเป็นรหัส URL สากล (เช่น %E0%B8...) ทำให้เปิดคลิปได้ 100%
    •

                    MikroTik RouterOS v7 Terminal
                    
                

                
# 1. สร้าง Interface WireGuard ตัวใหม่สำหรับ BPP-VMS (ไม่กระทบ VPN ตัวเดิม)
/interface wireguard

# 2. ผูก IP วง VPN ให้กับ Interface ใหม่
/ip address
add address=10.215.0.2/24 interface=wg-bppvms

# 3. เพิ่ม Peer เชื่อมโยงกลับมาที่ Server BPP-VMS
/interface wireguard peers
add interface=wg-bppvms \
    public-key="<Public_Key_ของ_Windows_Server>" \
    endpoint-address="bpp215.duckdns.org" \
    endpoint-port=51820 \
    allowed-address=10.215.0.0/24 \
    persistent-keepalive=25s \
    comment="Connect to BPP-VMS Server"

# 4. อนุญาตทราฟฟิกและทำ NAT ให้กล้องส่งภาพผ่านท่อ VPN ได้อย่างราบรื่น
/ip firewall nat
add chain=srcnat out-interface=wg-bppvms action=masquerade comment="NAT Camera over WG"

ขั้นตอนที่ 1: ติดตั้งและตั้งค่า WireGuard บน Cloud VPS (Ubuntu 22.04 / 24.04 หรือ Debian 12)

        

        

          เชื่อมต่อ SSH เข้าสู่ Cloud VPS ของคุณด้วยสิทธิ์ root แล้วคัดลอกชุดคำสั่งด้านล่างไปรันเพียงครั้งเดียว สคริปต์จะทำการติดตั้ง WireGuard, สร้างคีย์เข้ารหัส, เปิดระบบ Forwarding ของ Linux Kernel, และเปิด Service พร้อมใช้งานทันที:
        


        

          

            Linux Cloud VPS Terminal (Bash)
            
          

          
# ==============================================================================
# สคริปต์ติดตั้ง WireGuard Central Hub บน Cloud VPS (Linux Ubuntu/Debian)
# ==============================================================================

# 1. อัปเดตแพ็กเกจและติดตั้ง WireGuard
apt update && apt install -y wireguard iptables

# 2. เปิดระบบ IPv4 Forwarding ที่ระดับ Linux Kernel (สำคัญที่สุด: ให้ VPS ส่งต่อแพ็กเกจระหว่างสาขากับศูนย์)
sed -i 's/#net.ipv4.ip_forward=1/net.ipv4.ip_forward=1/' /etc/sysctl.conf
sysctl -p

# 3. เข้าสู่ไดเรกทอรี WireGuard และสร้างคีย์เข้ารหัสของตัว VPS Hub
cd /etc/wireguard
umask 077
wg genkey | tee server_private.key | wg pubkey > server_public.key

# แสดง Public Key ของ VPS ออกมาหน้าจอ (นำไปใส่ที่ MikroTik ทั้ง 2 ฝั่ง)
echo "=== VPS Public Key ของคุณคือ: ==="
cat server_public.key

# 4. ตรวจสอบชื่อ Network Interface หลักของ VPS (เช่น eth0, ens3, enp1s0)
WAN_IF=$(ip route get 8.8.8.8 | awk '{print $5; exit}')
echo "Network Interface คือ: $WAN_IF"

# 5. สร้างไฟล์คอนฟิก /etc/wireguard/wg0.conf
cat <<EOF > /etc/wireguard/wg0.conf
[Interface]
Address = 10.215.0.1/24
ListenPort = 51820
PrivateKey = $(cat server_private.key)

# กฎ iptables อนุญาตให้ Traffic ไหลข้ามระหว่าง Peer ได้โดยไม่ถูก Drop
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -A FORWARD -o wg0 -j ACCEPT
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -D FORWARD -o wg0 -j ACCEPT

# ------------------------------------------------------------------------------
# Peer 1: MikroTik ศูนย์ใหญ่ (HQ - ที่ตั้ง Server BPP-VMS)
# ------------------------------------------------------------------------------
[Peer]
# นำ Public Key จากคำสั่ง /interface wireguard print ของ MikroTik ศูนย์ใหญ่มาวาง
PublicKey = <PUBLIC_KEY_ของ_MIKROTIK_ศูนย์ใหญ่>
# อนุญาต IP VPN ของ HQ (10.215.0.2) และวง LAN ศูนย์ใหญ่ (192.168.1.0/24)
AllowedIPs = 10.215.0.2/32, 192.168.1.0/24

# ------------------------------------------------------------------------------
# Peer 2: MikroTik สาขาภาคสนาม (Branch - ที่ตั้งกล้อง CCTV)
# ------------------------------------------------------------------------------
[Peer]
# นำ Public Key จากคำสั่ง /interface wireguard print ของ MikroTik สาขามาวาง
PublicKey = <PUBLIC_KEY_ของ_MIKROTIK_สาขา>
# อนุญาต IP VPN ของสาขา (10.215.0.3) และวง LAN กล้องสาขา (192.168.10.0/24)
AllowedIPs = 10.215.0.3/32, 192.168.10.0/24
EOF

# 6. เปิดพอร์ตไฟร์วอลล์ 51820 UDP บน VPS
ufw allow 51820/udp || iptables -A INPUT -p udp --dport 51820 -j ACCEPT

# 7. เริ่มการทำงานของ WireGuard และตั้งให้เริ่มอัตโนมัติเมื่อเปิดเครื่อง
systemctl enable wg-quick@wg0
systemctl restart wg-quick@wg0

# 8. ตรวจสอบสถานะ Interface และ Peer
wg show

ขั้นตอนที่ 2: ตั้งค่า MikroTik ฝั่งศูนย์ใหญ่ (HQ - ยิงหา Cloud VPS)

        

        

          เปิดโปรแกรม Winbox หรือ SSH เข้าไปยัง MikroTik ศูนย์ใหญ่ (HQ) แล้วเปิดเมนู New Terminal นำสคริปต์นี้ไปวาง (อย่าลืมแทนที่ Public IP ของ VPS และ Public Key):
        


        

          

            MikroTik HQ Terminal (RouterOS v7)
            
          

          
# ==============================================================================
# คำสั่งตั้งค่า MikroTik ศูนย์ใหญ่ (HQ) ชี้หา Cloud VPS Relay
# ==============================================================================

# 1. สร้าง Interface WireGuard (ฝั่ง Client สุ่มพอร์ตฟังได้ หรือใช้ 13231)
/interface wireguard
add name=wg-vps listen-port=13231 mtu=1420 comment="Tunnel to Cloud VPS Relay"

# 2. ดู Public Key ของ MikroTik ศูนย์ใหญ่ (นำคีย์ที่ได้ไปใส่ในไฟล์ wg0.conf ของ VPS ที่ช่อง Peer 1)
/interface wireguard print

# 3. กำหนด IP ประจำตัวในวง VPN ให้เป็น 10.215.0.2
/ip address
add address=10.215.0.2/24 interface=wg-vps comment="HQ VPN IP"

# 4. เพิ่ม Peer ชี้ขึ้นไปหา Cloud VPS ตรงกลาง
# *** ข้อควรระวัง: ต้องใส่ persistent-keepalive=25s เสมอ มิฉะนั้นท่อจะหลุดเมื่อไม่มีทราฟฟิก ***
/interface wireguard peers
add interface=wg-vps     public-key="<PUBLIC_KEY_ของ_CLOUD_VPS>"     endpoint-address="203.0.113.10"     endpoint-port=51820     allowed-address=10.215.0.0/24,192.168.10.0/24     persistent-keepalive=25s     comment="Central Cloud VPS Hub"

# 5. เพิ่ม Static Route ชี้ว่าถ้าต้องการไปหาวงกล้องสาขา (192.168.10.0/24) ให้ส่งต่อผ่าน VPS (10.215.0.1)
/ip route
add dst-address=192.168.10.0/24 gateway=10.215.0.1 comment="Route to Branch Cameras via VPS"

# 6. Bypass Fasttrack ใน Firewall เพื่อป้องกันการสตรีมวิดีโอ RTSP UDP ถูกดร็อป
/ip firewall raw
add chain=prerouting src-address=192.168.10.0/24 action=accept comment="Bypass Fasttrack from Branch"
add chain=prerouting dst-address=192.168.10.0/24 action=accept comment="Bypass Fasttrack to Branch"

ตารางเจาะลึกพารามิเตอร์ 4 มิติ (Parameter Deep Dive Table)

        

        

          ชำแหละคำสั่งสำคัญของการตั้งค่า Cloud VPS Relay Hub แบบเจาะลึกทุกพารามิเตอร์ กว้างเต็มหน้าจอ 100%:
        


        

          

            
              

                1. พารามิเตอร์ / คำสั่ง
                2. คืออะไรในระบบ
                3. วิธีการทำงานเชิงลึก
                4. ทำทำไม & ถ้าไม่ใส่เกิดอะไรขึ้น
              

            
            
              

                persistent-keepalive=25s
                Heartbeat Pulse (คำสั่งรักษาท่อ)
                สั่งให้ MikroTik ส่งแพ็กเก็ต UDP เปล่าขนาดเล็กไปยัง VPS ทุกๆ 25 วินาที เพื่อรีเฟรชตาราง State บน NAT Firewall ของโอเปอเรเตอร์ 4G
                หัวใจสำคัญที่สุด! หากไม่ใส่ ไฟร์วอลล์ CGNAT จะตัดท่อทิ้งเมื่อไม่มีข้อมูลวิ่งเกิน 30-60 วินาที ทำให้ศูนย์ใหญ่ดึงภาพกล้องไม่ได้อีกเลย
              

              

                AllowedIPs (ทั้งบน VPS และ MikroTik)
                Cryptographic Routing Filter
                ทำหน้าที่ 2 อย่างพร้อมกัน: 1) ทำตัวเป็น ACL กรองแพ็กเก็ตที่อนุญาตให้วิ่งผ่านคีย์ และ 2) สร้าง Kernel Routing Table อัตโนมัติในท่อ
                ต้องใส่ทั้ง IP ของตัว VPN (/32) และวง LAN ของไซต์ปลายทาง (/24) หากไม่ใส่ วงแลนจะไม่สามารถคุยข้ามไซต์กันได้
              

              

                net.ipv4.ip_forward=1
                Linux Kernel Packet Router
                สั่งให้ Linux OS บน VPS ยอมทำหน้าที่เป็นเราเตอร์ส่งต่อ IP แพ็กเก็ตจาก Interface ขาเข้า (wg0 จากสาขา) ไปยัง Interface ขาออก (wg0 สู่ HQ)
                หากไม่เปิดคำสั่งนี้ VPS จะปฏิเสธการส่งต่อแพ็กเก็ตข้าม Peer ทำให้ Ping หากันไม่เจอ แม้ WireGuard จะต่อติดแล้วก็ตาม
              

              

                mtu=1420
                Maximum Transmission Unit
                ลดขนาดเฟรมข้อมูลลงจากปกติ 1500 ไบต์ เหลือ 1420 ไบต์ เพื่อชดเชยพื้นที่สำหรับ WireGuard Header (32 ไบต์) และ UDP/IP Header
                หากไม่ปรับ ภาพสตรีม RTSP จากกล้องอาจเกิด Packet Fragmentation ส่งผลให้ภาพกระตุก สีแตก หรือขึ้นแถบสีเทาครึ่งจอ
              

              

                Fasttrack Bypass (/ip firewall raw)
                Connection Tracking Bypass
                ดักจับทราฟฟิกของวงแลนสาขาและศูนย์ใหญ่ที่วิ่งผ่าน VPN ไม่ให้เข้าสู่ Fastpath Engine ของ MikroTik RouterOS
                ฟีเจอร์ Fasttrack ของ RouterOS มักทำให้แพ็กเก็ต UDP ของกล้องวงจรปิดหลุดออกจากท่อ VPN แล้วรั่วออกสู่อินเทอร์เน็ตปกติ

              • ต้องมี Public IP บนซิม
• ต้องตั้ง Virtual Server บนเราเตอร์
            

          


          
          

            ไม่ต้องตั้งเราเตอร์
            
3. กล้องยิง RTMP Push ตรง

              • ตัวกล้องต้องรองรับเมนู RTMP
• Server เปิดรับพอร์ต 1935
            

          


          
          

            
4. Reverse Tunnel (FRP / Cloudflare)

            

              สำหรับรีโมทเปิดหน้า Web GUI ของกล้องวงจรปิดหรือหน้าตั้งค่าเราเตอร์ข้ามเครือข่าย เพื่อปรับมุมกล้อง รีบูต หรือแก้รหัสผ่านจากระยะไกล
            

            

              • รัน FRP Client บนเราเตอร์/กล่องเล็ก
• ทะลุ CGNAT สู่ Web Dashboard

          RTSP (Real Time Streaming Protocol) คือโปรโตคอลมาตรฐานที่ใช้ส่งสัญญาณภาพวิดีโอจากกล้องวงจรปิดเข้าสู่ระบบ VMS โดยมีโครงสร้างมาตรฐานดังนี้:
        


        
        

          

            rtsp://admin:Password123@192.168.10.50:554/Streaming/Channels/102
          

          

            
rtsp:// = โปรโตคอลสตรีมมิ่ง

            
admin:Pass@ = Username & Password

            
192.168.10.50 = IP Address กล้อง

            
:554 = พอร์ตมาตรฐาน RTSP

            
/Path... = ตำแหน่งแชนแนล & สตรีม

          

        


        
        

          
💡 กฎเหล็ก AI VMS: ความแตกต่างระหว่าง Mainstream vs Substream

          

            

              1. Substream (สตรีมย่อย - ความละเอียดต่ำ เช่น 640x360 หรือ 720p):
              
• ใช้สำหรับ Frigate AI Object Detection ตลอด 24 ชม.
              
• ประหยัดเน็ตซิม 4G มหาศาล (บิตเรตเพียง 0.5 - 1 Mbps ต่อกล้อง)
              
• ลดภาระ CPU / GPU ของเซิร์ฟเวอร์แม่ข่ายลงมากกว่า 70-80%
            

            

              2. Mainstream (สตรีมหลัก - ความละเอียดสูง 1080p, 2K, 4K):
              
• ใช้สำหรับ บันทึกวิดีโอหลักฐาน (Recording) และ ซูมอ่านป้ายทะเบียน (LPR)
              
• ดึงเฉพาะช่วงที่มีการตรวจจับพบเหตุการณ์ หรือดึงภาพบันทึกลง NVR ฝั่งสาขา

            📡 เจาะลึกโปรโตคอล RTMP
            
วิธีการค้นหาและแกะสตรีม RTMP (พอร์ต 1935) ของกล้องวงจรปิดทุกประเภท

          


          

            RTMP (Real-Time Messaging Protocol - พอร์ต TCP 1935) คือโปรโตคอลสตรีมมิ่งที่ทำงานแบบ "Push สตรีม" (กล้องเป็นฝ่ายส่งภาพออกไปหาแม่ข่าย) ซึ่งเป็น ทางออกกู้ชีพอันดับ 1 สำหรับกล้องที่ใส่ซิม 4G/5G, กล้องโซล่าเซลล์ หรือสาขาที่ Router ติดปัญหา Private IP / CGNAT ที่ไม่สามารถ Forward Port RTSP หรือต่อ VPN เข้ามาได้
          


          
          

            

              
                

                  คุณสมบัติเปรียบเทียบ
                  RTSP (Real-Time Streaming Protocol)
                  RTMP (Real-Time Messaging Protocol)
                

              
              
                

                  พอร์ตมาตรฐาน
                  TCP 554
                  TCP 1935
                

                

                  ทิศทางการเชื่อมต่อ
                  Pull: เซิร์ฟเวอร์ต้องวิ่งไป "ดึงภาพ" จากกล้อง
                  Push: กล้องเป็นฝ่าย "ยิงภาพ" ส่งมาให้เซิร์ฟเวอร์
                

                

                  ข้อจำกัดเน็ตซิม 4G / CGNAT
                  ❌ ต้องมี Public IP / DDNS หรือต่อท่อ VPN จึงจะดึงได้
                  ✅ ทะลวงเน็ตซิมได้ทันที 100% ขอเพียง Server มี Public IP / Domain
                

                

                  โครงสร้าง URL
                  rtsp://user:pass@camera_ip:554/live
                  rtmp://server_ip:1935/live/stream_name
                

                

                  การใช้งานใน BPP-VMS
                  กล้องในวง LAN เดียวกัน หรือต่อข้าม WireGuard VPN
                  กล้องด่านตรวจชั่วคราว / กล้องโซล่าเซลล์กลางป่า / จุดไร้สาย
                

              
            

          


          
          
🛠️ 4 ขั้นตอนการแกะหาและตั้งค่า RTMP ของกล้องวงจรปิดทุกประเภท:


          

            
            
            

              

                1
                
เปิดเมนู RTMP Push บนหน้า Web กล้องโดยตรง

              

              

                กล้อง IP ยุคใหม่เกือบทุกยี่ห้อมีฟีเจอร์ RTMP Push ในตัวสำหรับไลฟ์สดหรือส่งขึ้นคลาวด์:
              

              
    
                
  • Hikvision / HiLook: เข้า Configuration ➔ Network ➔ Advanced Settings ➔ RTMP ➔ ติ๊กถูกที่ Enable ➔ Server Type เลือก Customized ➔ กรอก URL: rtmp://vms.local:1935/live/cam_chk01
    • 
                
  • Dahua / Imou (ผ่าน NVR): เข้า Setting ➔ Network ➔ Access Platform ➔ RTMP ➔ เปิด Enable ➔ Address Type: Custom
    • 
                
  • Uniview (UNV): เข้า Setup ➔ Network ➔ Network Service ➔ RTMP Push ➔ เปิด Enable
    • 
                
  • กล้อง 4G โซล่าเซลล์ (V380 / Tuya / Yoosee): เปิดแอป ➔ เมนู PC View / RTMP Live ➔ เปิดสวิตช์แล้วใส่ URL เซิร์ฟเวอร์
    • 
              

            


            
            

              

                2
                
สแกนพอร์ต 1935 เช็กว่ากล้องเปิดรับ RTMP หรือไม่

              

              

                กล้องและ NVR บางรุ่นทำตัวเป็น RTMP Server ให้ดึงภาพออกได้ (Pull RTMP):
              

              

                
คำสั่งทดสอบบน PowerShell:

                
Test-NetConnection -ComputerName 192.168.1.50 -Port 1935

                
หรือใช้ nmap:

                
nmap -p 1935 192.168.1.50

              

              

                หากผลลัพธ์ขึ้นว่า TcpTestSucceeded : True แสดงว่ากล้องรองรับ สามารถดึงภาพผ่าน rtmp://192.168.1.50:1935/live/ch0 หรือ /bcast/ch0 ได้ทันที
              

            


            
            

              

                3
                
ใช้ Wireshark ดักจับแพ็กเก็ต RTMP Handshake

              

              

                ในกรณีที่กล้องไม่มีเมนูบอกชัดเจน หรือเป็นกล้อง Smart Camera ที่สตรีมผ่านแอป:
              

              
    
                
  1. ต่อคอมพิวเตอร์เข้าวงแลนหรือปล่อย Wi-Fi Hotspot ให้กล้องเชื่อมต่อ
    2. 
                
  2. เปิดโปรแกรม Wireshark ➔ ใส่ฟิลเตอร์: rtmp || tcp.port == 1935
    3. 
                
  3. เปิดแอปดูกล้อง ➔ ค้นหาแพ็กเก็ตคำสั่ง connect หรือ publish
    4. 
                
  4. คลิกดูรายละเอียดของแพ็กเก็ต จะพบทั้ง App Name (เช่น live) และ Stream Key สามารถนำชุด URL นั้นมาใช้งานได้ทันที
    5. 
              

            


            
            

              

                4
                
แปลง RTSP กล้องธรรมดาเป็น RTMP Push ด้วย FFmpeg

              

              

                หากกล้องที่หน้างานไม่มีเมนู RTMP แต่ต้องส่งภาพผ่านเน็ตซิม 4G สามารถใช้ Mini PC, Raspberry Pi หรือคอมพิวเตอร์ที่ด่านตรวจรันคำสั่งนี้เพื่อยิงภาพเข้าเซิร์ฟเวอร์หลัก:
              

              

                
ffmpeg -re -rtsp_transport tcp -i "rtsp://admin:pass@192.168.1.50:554/stream" \
  -c:v copy -c:a aac -f flv "rtmp://:1935/live/cam_chk01"

              

              

                💡 เคล็ดลับ: การใช้พารามิเตอร์ -c:v copy จะเป็นการส่งต่อบิตเรตดั้งเดิมของกล้องโดยไม่เข้ารหัสใหม่ ใช้ CPU ไม่ถึง 1% และภาพไม่ดีเลย์
              

            


          


          
          

            

              📡 วิธีตั้งค่า BPP-VMS (Frigate go2rtc) ให้รอรับสตรีม RTMP:
            

            

              ในระบบ BPP-VMS เซิร์ฟเวอร์ Frigate NVR ได้เปิดพอร์ต 1935:1935 ไว้แล้ว เมื่อกล้องยิงสตรีมเข้ามา ให้แมปชื่อสตรีมในไฟล์ config.yml ดังนี้:
            

            
go2rtc:
  streams:
    # ชื่อสตรีมต้องตรงกับชื่อ Stream Key ที่กล้องยิงมา (/live/cam_checkpoint_01)

      - "rtmp://127.0.0.1:1935/live/cam_checkpoint_01"

cameras:
  cam_checkpoint_01:
    ffmpeg:
      inputs:
        - path: rtsp://127.0.0.1:8554/cam_checkpoint_01
          roles:
            - detect
            - record

          


          
          

            

              🛡️ คู่มือปลดล็อคพอร์ต 1935 (Firewall & Port Forwarding)
            

            
            
            

              

                💡 1. URL `rtmp://127.0.0.1...` ต้องเอาไปกรอกที่เครื่องไหน?

                ให้กรอกในไฟล์ frigate.yml (หัวข้อ go2rtc) บนเครื่อง เซิร์ฟเวอร์ BPP-VMS (ศูนย์กลาง) เท่านั้น ไม่ใช่เครื่องหน้างาน เพราะการระบุ 127.0.0.1:1935 เป็นการสั่งให้ Frigate ดึงสตรีมจากตัวรับของมันเองที่รอรับการ Push มาจากหน้างานอยู่แล้ว
              

            


            

              
              
              

                
🖥️ ฝั่งที่ 1: เครื่องหน้างาน (Windows Bridge)

                
ต้องเปิด Outbound Port 1935 เพื่ออนุญาตให้ยิงสตรีมออกไปได้

                
                
วิธีที่ 1 (สายด่วน): เปิด PowerShell (Run as Admin) วางคำสั่งนี้:

                
New-NetFirewallRule -DisplayName "BPP-VMS RTMP Outbound" -Direction Outbound -LocalPort 1935 -Protocol TCP -Action Allow

                
                
วิธีที่ 2 (สาย GUI):

                
    
                  
  1. ค้นหา Windows Defender Firewall with Advanced Security
    2. 
                  
  2. คลิก Outbound Rules > New Rule...
    3. 
                  
  3. เลือก Port > TCP > ระบุพอร์ต 1935
    4. 
                  
  4. เลือก Allow the connection > ตั้งชื่อ "BPP-VMS RTMP"
    5. 
                

              


              
              

                
🏢 ฝั่งที่ 2: เซิร์ฟเวอร์ศูนย์สั่งการ (BPP-VMS)

                
ต้องตั้ง Port Forwarding Inbound 1935 ชี้มาที่ไอพีเซิร์ฟเวอร์

                
                
กรณีที่ 1: ศูนย์ใช้ MikroTik (เสียบสายด่วนใน Terminal):

                
/ip firewall nat add chain=dstnat dst-port=1935 action=dst-nat protocol=tcp to-addresses=[IP_BPP_VMS_SERVER] to-ports=1935 comment="BPP-VMS RTMP 1935"

                
*ถ้าใช้ Winbox: `IP > Firewall > NAT > Add (dstnat, tcp, 1935) > Action (dst-nat, [IP])`

                
                
กรณีที่ 2: ใช้เร้าเตอร์ทั่วไป (AIS/3BB/True)

                
ล็อคอินเข้าเร้าเตอร์ (เช่น 192.168.1.1) หาเมนู Port Forwarding / Virtual Server ตั้ง External Port 1935 ชี้ไปยัง Internal IP ของเซิร์ฟเวอร์ BPP-VMS (Port 1935)


                
กรณีที่ 3: ไม่มี Public IP (CGNAT)

                
ให้ใช้ Tailscale หรือ ZeroTier ติดตั้งทั้ง 2 ฝั่งเพื่อจำลองวงแลน (VPN) ข้ามเน็ต โดยใช้ IP วง VPN แทนการ Forward Port

กลยุทธ์ Dynamic DDNS เมื่อไม่มี Fix IP และไม่มี Domain (ครอบคลุมทุกกรณี)

            

            

                ในทางปฏิบัติหน้างาน จุดติดตั้งส่วนใหญ่จะไม่มี Fix Public IP หรือบางจุดใช้เน็ตซิม 4G/5G ให้เลือกใช้กลยุทธ์ตามระดับความยากของสถานที่:
            

        


        

            

                
1

                
กรณีที่ 1 (ระดับง่ายสุด): ใช้ MikroTik IP Cloud DDNS (ฟรีในตัวเครื่อง 100%)

            

            

                MikroTik ทุกตัวมีฟังก์ชัน DDNS ที่ผูกกับ Serial Number ของอุปกรณ์ให้ฟรีตลอดชีพโดยไม่ต้องซื้อโดเมนและไม่ต้องสมัครสมาชิกใดๆ:
            


            

                

                    MikroTik Terminal (ฝั่งศูนย์หลัก)
                    
                

                
# 1. สั่งเปิดใช้งาน IP Cloud DDNS
/ip cloud set ddns-enabled=yes ddns-update-interval=1m update-time=yes

# 2. ดูชื่อ Domain ที่ระบบสุ่มให้จาก Serial Number
/ip cloud print

            


            

                💡 วิธีนำไปใช้งาน: ในผลลัพธ์ของคำสั่ง print จะมีบรรทัด dns-name: xxxxxxxxxxxx.sn.mynetname.net ให้นำชื่อโดเมนนี้ไปใส่ในช่อง endpoint-address ของ MikroTik ฝั่งสาขาได้ทันที
            

        


        

            

                
2

                
กรณีที่ 2 (ระดับกลาง): ใช้ DuckDNS ผ่าน RouterOS Script (กรณีต้องการชื่อจำง่าย)

            

            

                กรณีต้องการชื่อจำง่าย เช่น bpp215-hq.duckdns.org สามารถสร้างสคริปต์ใน MikroTik เพื่อตรวจจับว่าเมื่อ WAN IP เปลี่ยนแปลง ให้ส่งคำขอ HTTPS ไปอัปเดต DuckDNS อัตโนมัติ:
            


            

                

                    MikroTik Script & Scheduler Setup
                    
                

                
# 1. สร้างสคริปต์อัปเดต IP ไปยัง DuckDNS
/system script
add name="update-duckdns" source={
    :local domain "bpp215-hq"
    :local token "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
    :local wanInterface "ether1"
    :local currentIP [/ip address get [find interface=$wanInterface] address]
    :set currentIP [:pick $currentIP 0 [:find $currentIP "/"]]
    
    :global previousIP
    :if ($currentIP != $previousIP) do={
        :log info ("[DuckDNS] WAN IP changed to " . $currentIP . ", updating...")
        /tool fetch mode=https url=("https://www.duckdns.org/update\?domains=" . $domain . "&token=" . $token . "&ip=" . $currentIP) keep-result=no
        :set previousIP $currentIP
    }
}

# 2. ตั้ง Schedule ให้รันสคริปต์ตรวจสอบทุก 5 นาที
/system scheduler
add name="schedule-duckdns" interval=5m on-event="update-duckdns"

            

        


        

            

                
3

                
กรณีที่ 3 (ระดับยากสุด): กรณีติด Private IP / 4G / CGNAT ทั้ง 2 ฝั่ง (ไม่มี Public IP เลย)

            

            

                ในพื้นที่ทุรกันดารหรือป้อมด่านตรวจที่ใช้เน็ตซิม 4G/5G ทั้งสองฝั่ง จะได้ IP วง 100.64.x.x (CGNAT) ทั้งคู่ ทำให้ไม่สามารถตั้ง WireGuard Listen Port เพื่อรอรับ Inbound ได้โดยตรง:
            


            

                🛑 ข้อจำกัดของเครือข่าย: เมื่อไม่มีฝั่งใดมี Public IP แท้ ท่อ VPN แบบ Direct P2P จะไม่สามารถจับมือ Handshake กันได้เลย
            


            
ทางออกและแนวทางแก้ไขที่ดีที่สุด:

            
    
                
  1. ทางเลือกที่ 1 (แนะนำที่สุด): ใช้ Cloud VPS Relay เป็นตัวกลาง (~100 บาท/เดือน)
                    
    เช่า Cloud VPS สเปกเล็กสุดที่มี Public IP แท้ (เช่น DigitalOcean หรือ VPS ในไทย) แล้วติดตั้ง WireGuard Server ไว้ที่นั่น จากนั้นให้ทั้ง MikroTik ศูนย์ และ MikroTik สาขา เป็น Client ยิง Outbound ขึ้นหา VPS ทั้งคู่ ภาพกล้องจะวิ่งผ่าน VPS Relay โดยไม่มีปัญหาเรื่อง CGNAT อีกต่อไป
                
    2. 
                
  2. ทางเลือกที่ 2: ใช้บริการ THAI DDNS / True DDNS Port Forward
                    
    ผู้ให้บริการอินเทอร์เน็ตบางราย (เช่น AIS Fibre) มีบริการ THAI DDNS ฟรีที่จะเปิดพอร์ตพิเศษ (เช่น 25182) ทะลุ CGNAT มายังบ้านเราได้
                
    3. 
                
  3. ทางเลือกที่ 3: ติดตั้ง Tailscale หรือ ZeroTier บน RouterOS v7
                    
    RouterOS v7 รองรับแพ็กเกจ ZeroTier/Tailscale ช่วยทำ Mesh VPN ข้าม CGNAT อัตโนมัติผ่านโปรโตคอล DERP/STUN Relay
                
    4. 
            

        


    


    
    
    
    

        
        

            

                
⚡

                
ระบบตรวจจับอัตโนมัติ (Auto-Detect) & กู้คืนตัวเอง (Auto-Healing) ไม่ให้ VPN หลุดค้าง

            

            

                จุดอ่อนสำคัญของ WireGuard บน MikroTik: เมื่อ RouterOS แปลงชื่อ Hostname (DDNS) เป็น IP ครั้งแรกแล้ว มันจะ จำค่า IP นั้นไว้ตลอดไป หากศูนย์ใหญ่ IP เปลี่ยน (เน็ตตัด/ไฟดับ) สาขาจะไม่ยอม Re-resolve DNS ใหม่ ทำให้ท่อค้างถาวร!
            

            

                ติดตั้ง 2 สคริปต์นี้เพื่อแก้ปัญหาดังกล่าว 100%:

สคริปต์ที่ 1: Dynamic DNS Endpoint Auto-Resolver (ตรวจจับ IP เปลี่ยนแปลง)

            

            

                สคริปต์นี้จะ Resolve หา IP ปัจจุบันของชื่อ DDNS อยู่ตลอดเวลา หากพบว่า IP เปลี่ยนไปจากที่ Peer กำลังจำอยู่ จะสั่งอัปเดต Endpoint Address ของ Peer ทันที:
            


            

                

                    MikroTik Script: wg-endpoint-resolver
                    
                

                
# 1. สร้าง Script ตรวจจับและอัปเดต IP ให้กับ Peer
/system script
add name="wg-endpoint-resolver" source={
    :local peerComment "Peer to HQ"
    :local endpointHost "bpp215.duckdns.org"
    
    :do {
        :local resolvedIP [:resolve $endpointHost]
        :local currentEndpoint [/interface wireguard peers get [find comment=$peerComment] endpoint-address]
        
        :if ($resolvedIP != $currentEndpoint) do={
            :log warning ("[WireGuard-DNS] Endpoint IP changed from " . $currentEndpoint . " to " . $resolvedIP . ". Updating peer...")
            /interface wireguard peers set [find comment=$peerComment] endpoint-address=$resolvedIP
        }
    } on-error={
        :log error ("[WireGuard-DNS] Failed to resolve hostname: " . $endpointHost)
    }
}

# 2. ตั้ง Schedule ให้รันตรวจสอบทุก 2 นาที
/system scheduler
add name="schedule-wg-resolver" interval=2m on-event="wg-endpoint-resolver"

                    MikroTik Netwatch Watchdog Setup
                    
                

                
/tool netwatch
add host=10.215.0.1 interval=30s timeout=3s type=icmp comment="Watchdog BPP-VMS Tunnel" \

                            2. ตรวจสอบ Public Key ของทั้ง 2 ฝั่ง

                        2. เน็ตตัดแล้วต่อไม่ติด (DNS ค้าง)
                        MikroTik ไม่ยอม Re-resolve DNS ใหม่ของชื่อ DDNS
                        ติดตั้งสคริปต์ wg-endpoint-resolver ในแท็บที่ 4 เพื่อให้อัปเดต IP อัตโนมัติ
                    

                    

                        3. Ping เจอ แต่ภาพกล้องไม่ขึ้น / หมุนติ้ว
                        ทราฟฟิกกล้องถูก MikroTik Fasttrack ข้ามคิวการเข้ารหัส VPN
                        
                            ใส่ Rule ข้าม Fasttrack ไว้ที่บรรทัดบนสุด (place-before=0):

                            /ip firewall filter add chain=forward action=accept src-address=192.168.88.0/24 dst-address=192.168.1.0/24 place-before=0
                        		
                    

                    

                        4. ภาพกล้องแตก กระตุก มีแถบเทา (MTU แตก)
                        MTU เริ่มต้น 1500 ใหญ่เกินไป ถูกเน็ต 4G/PPPoE ตัดทอนแพ็กเก็ต
                        
                            ปรับ MTU WireGuard Interface เป็น 1420 ทั้งสองฝั่ง:

                            /interface wireguard set [find] mtu=1420
                        		
                    

                    

                        5. กล้องสาขาไม่ตอบสนองข้ามท่อ VPN
                        กล้องไม่ได้ตั้ง Default Gateway ชี้มาที่ IP MikroTik
                        
                            1. ตั้ง Gateway ในกล้องเป็น IP MikroTik (เช่น 192.168.88.1)

                            2. หรือใส่ NAT Masquerade ขาออก WireGuard Interface
                        		
                    

                    

                        6. CPU MikroTik วิ่ง 100% เครื่องร้อน
                        ดึงภาพ 4K Mainstream หลายกล้องผ่านเราเตอร์ตัวเล็กพร้อมกัน
                        ใน Frigate NVR ให้เลือกดึง Substream (640x360 หรือ 720p) สำหรับตรวจจับ AI
                    

                    

                        7. IP หลุดบ่อยเกินไป (เน็ตตัดทุก 24 ชม.)
                        ISP ทำการรีเซ็ต IP ทุกวัน ทำให้ท่อค้างเป็นช่วงๆ
                        ปรับช่วงเวลาของตัวตั้งเวลา schedule-wg-resolver ให้ถี่ขึ้นเป็น 1m
                    

                    

                        8. อัปเกรด RouterOS แล้วคอนฟิกหาย
                        ไม่มีการส่งออกคำสั่ง Backup ก่อนทำการอัปเดตเฟิร์มแวร์
                        
                            Export คำสั่งเก็บไว้ในคอมพิวเตอร์เสมอ:

                            /export file=backup-wireguard

วิธีตรวจจับว่าอินเทอร์เน็ต "ติด CGNAT" หรือไม่? (เช็ค 2 ขั้นตอนใน 30 วินาที)

            


            

                Carrier-Grade NAT (CGNAT) คือการที่ค่ายเน็ตแชร์ IP สาธารณะตัวเดียวให้คนใช้ร่วมกันนับร้อยบ้าน ทำให้เราเตอร์ของท่านไม่ได้ Public IP ตัวจริง:
            


            

                

                    
ขั้นตอนที่ 1: ดู WAN IP ในหน้าเราเตอร์

                    

                        ล็อกอินเข้าหน้าเว็บ 192.168.1.1 ➔ เมนู Status / Device Info ➔ สังเกตค่า WAN IPv4 Address
                    

                    

                        ตัวอย่างที่พบ: 100.64.12.89
                    

                


                

                    
ขั้นตอนที่ 2: ดู IP สาธารณะบนเว็บจริง

                    

                        เปิดเบราว์เซอร์เข้าเว็บไซต์ whatismyipaddress.com หรือ checkip.amazonaws.com
                    

                    

                        ตัวอย่างที่พบ: 1.47.120.35
                    

                

            


            

                

                    ❌ ผลลัพธ์: ติด CGNAT 100%

                    เมื่อ WAN IP ในเราเตอร์ ไม่ตรงกับ IP บนเว็บ และขึ้นต้นด้วย 100.64.x.x ถึง 100.127.x.x (RFC 6598) หรือวง 10.x.x.x / 172.16-31.x.x

                    ➔ ฟอร์เวิดพอร์ตไปก็ไม่มีผล ต้องโทรขอปลด หรือใช้เทคนิคในหัวข้อถัดไป
                


                

                    ✅ ผลลัพธ์: ได้ Public IP จริง 100%

                    เมื่อ WAN IP ในเราเตอร์ ตรงกันเป๊ะ กับ IP บนเว็บ เช่น ในเราเตอร์ขึ้น 1.47.120.35 และบนเว็บก็ขึ้น 1.47.120.35

                    ➔ ท่านสามารถ Forward Port และใช้ MikroTik Cloud DDNS ได้สมบูรณ์แบบ

                    🥈 วิธีที่ 2: ใช้ Cloud VPS WireGuard Relay (กรณีเน็ตซิม 4G ทั้งสองฝั่ง - งบ 100-150 บาท/เดือน)
                

                

                    เมื่อทั้งศูนย์ใหญ่และกล้องสนามต่างใช้ซิม 4G ติด Double CGNAT ทั้งคู่ ให้เช่า Cloud VPS ขนาดเล็ก (1 vCPU, 1GB RAM) ที่มี Fix Public IP มารับทราฟฟิกตรงกลาง
                

                

                    

                        คำสั่ง Docker 1-Click รัน WireGuard Relay บน Linux VPS
                        
                    

                    
docker run -d \
  --name=wg-relay \
  --cap-add=NET_ADMIN \
  --cap-add=SYS_MODULE \
  -e PUID=1000 \
  -e PGID=1000 \
  -e TZ=Asia/Bangkok \
  -e SERVERURL=<PUBLIC_IP_ของ_VPS> \
  -e SERVERPORT=51820 \
  -e PEERS=hq_server,camera_branch1 \
  -e PEERDNS=auto \
  -p 51820:51820/udp \
  -v /opt/wireguard/config:/config \
  --sysctl="net.ipv4.conf.all.src_valid_mark=1" \
  --sysctl="net.ipv4.ip_forward=1" \
  --restart unless-stopped \
  linuxserver/wireguard:latest
